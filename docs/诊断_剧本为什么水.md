# 诊断：剧本为什么会“水”

> 结论先行：**不是文笔问题，是系统问题。** 旧链路把 99.8% 的注意力给了长篇小说工艺，把 0.18% 给了人生副本；拆解产出的是 1.4 万字的文艺评论而不是施工图；成品没有 beat 时钟、没有台词交换；门禁测不到“好看”，却给出 PASS。
> 本文所有数字都可以在仓库里复核（命令见每节末尾）。

---

## 1. 注意力错位：3.4M 字规则，人生副本占 0.18%

| 项 | 数量 |
|---|---|
| 归档的旧链路总字符 | **3,427,557**（507 个文件） |
| 其中“人生副本”真正的手艺文件（profile + Agent 方法 + 通用骨架） | **6,259 字符 = 0.18%** |
| 面向长篇/短篇小说工艺的 references | **310 个 .md 文件** |

写口播剧的人打开仓库，先撞上的是 Reference Gate、付费点、十二列表格、去味清零表——**手艺被规则淹没**。规则写得越多，越像在写“如何写作”的论文，而不是在写戏。

复核：`python3 - <<'PY'` 统计 `archive/旧链路` 的字符数并与三个 profile 文件对比（本次运行输出 3,427,557 / 6,259 / 0.18%）。

## 2. 提料错位：拆解报告 1.4 万字/篇，却不产出可施工的结构

| 项 | 数量 |
|---|---|
| 拆文库 | 873 个文件、**6,289,110 字符**、54 个条目 |
| 拆文报告平均长度 | **13,782 字/篇**（中位 14,653）—— 约为原文的 4.3 倍 |
| 含“钩子/hook”讨论 | 52 / 54 |
| 含**功能位** | **7 / 54** |
| 含**阻力/证据阶梯** | **11 / 54** |
| 含**秒级时长** | **17 / 54** |

拆文报告写的是“叙事时间线、时间操控目的、情绪曲线、五维评分”——这些是**评论**，不是**施工图**。
写作时没有任何“谁在争什么、对手加价几轮、兑现什么、留下什么债”的图纸可抄，于是每一篇都从零开始凭感觉编，最后只能靠**梗和顺口句**把时长填满——这就是“水”的直接来源。

## 3. 产物形态错位：成品是“分行散文”，不是能念的剧本

以 `作品/80`（用户直接点名“看不懂、流水账”）为例：

| 指标 | 旧稿 80 | 样本 001（新工厂） |
|---|---|---|
| 口播字数 / 估算时长 | 1117 字 ／ 旧系统按 6.4 字/秒＝175s（按可念的 4.2 字/秒＝**266s**） | 527 字 ／ **125s**（目标 120s） |
| **beat 秒窗** | **0 个**（没有一格知道自己负责第几秒） | **7 个**（每格带起止秒与功能） |
| 带说话人的台词 | **0 行**（对白被压成裸行旁白，念稿时分不出谁在说） | 26 条，占字数 **42%** |
| 空间行占比 | 11% | 26% |
| 时间标签裸句 | 11 行 | 0 |
| 体检 | 机检 PASS / BLOCK·REVIEW 双零 | BLOCK 0 / WARN 0，且明列 5 项“不测” |

口播剧的三个硬指标——**时长契约、台词占比、每 15 秒一个钩子**——旧稿一个都没有写进契约，写的时候也没有人验。

## 4. 门禁空转：测不到“好看”，却敢发 PASS

`scripts/fuben_policy.json` 的 10 条创作规则里，**6 条被显式设为 `null`**（beat 数、情绪峰值位置、对白比例、感官词数、呼应次数、字数）——“放弃可测性”被写进了策略文件。

结果：
- `05_机检.json`：`status: PASS`、`BLOCK/REVIEW 双零`，同时 `editorially_approved: false`、`release_ready: false`；
- 用户看完的判断：**看不懂、是流水账**；
- 没有任何机械环节能把这两件事接起来 → **PASS 幻觉**：流程通过越多，越没人敢说不好看。

## 5. 无资产沉淀：同一题写三遍，每次重来

- `作品/79`：`旧版/` + `_运行_v1/` + `_运行_v2/` + 现行版 —— **同一题三个版本**；
- `作品/80`：`_运行/` 13 份产物（`02/02b/02c` 三版初稿、`03/03b` 两轮审读、`04/04b` 两轮返工、`05/05b` 两次机检、`06` 勘误、`07` 诊断）；
- 没有骨架库、没有钩子库、没有母版与改编链 —— 于是**返工只能重写，不能复用**，质量不累积、产能不累积。

## 6. 判型缺失：把长剧流程借了进来，先没判这是什么片

旧链路照搬了 `YingaoZhang/short_drama_agent` 的四阶段（策划 → 主笔 → 审读 → 返工）。那套流程服务的是**戏剧驱动的剧集**；而人生副本是**文案驱动形态 + 戏剧驱动内核**。判型没做，直接后果是：

- 审读按小说的尺子量口播剧（伏笔、侧面描写、心理与旁白），于是**旁白替人物打架**；
- 口播需要的“换气、秒表、台词交换”没人量；
- 反过来，重写了三版初稿也修不好“听不懂”——因为病根在形态，不在句子。

---

## 修法：新工厂对着六个病根各下一刀

| 病根 | 修法 | 落在哪 |
|---|---|---|
| 注意力错位 | 规则瘦身：一个 SKILL + 8 个 reference，一屏读完入口 | `剧本工厂/SKILL.md`、`references/` |
| 提料错位 | 机器蒸馏 44 篇指纹 + 真实开场原句库；人工校准 6 个骨架 | `剧本工厂/scripts/distill.py`、`资产/`、`references/骨架库.md` |
| 形态错位 | beat 时钟契约 + 字数×秒 + 台词内联 + 分行＝换气 | `templates/剧本.md`、`references/口播语法.md` |
| 门禁空转 | `fuben_check.py` 只判可测项，明列“不测的项”，sha 绑定正文 | `scripts/fuben_check.py`、`references/验收表.md` |
| 无沉淀 | 骨架库 + 指纹协议 + 高保真改编（锁 9 项换壳） | `references/骨架库.md`、`结构指纹协议.md`、`高保真改编.md` |
| 判型缺失 | 判型卡两问：观众要“说什么”还是“发生什么” | `references/判型卡.md` |

## 怎么验证修好了（三条硬标准）

1. **可念**：拿稿子念一遍，掐表与目标差 ≤10%；念稿时能听出谁在说话。
2. **可判**：`fuben_check.py` 有 BLOCK 就必须修；PASS 之后，仍然只有“人”能批准，且体检里写着哪些是没测的。
3. **可复用**：同一个骨架能改编出第 2、3 条片子，改编后锁定项没有被稀释（对照表在 `高保真改编.md`）。
