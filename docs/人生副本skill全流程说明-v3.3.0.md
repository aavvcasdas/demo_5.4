# 人生副本 skill · 全流程说明书（v3.3.0，2026-10-02）

> 写给第一次接触这个仓库的人看。读完你应该能：知道每个文件夹/文件是干什么的、知道 AI 拿到一个题面之后会按什么顺序做事、知道每一步产出什么、知道哪些检查是机器做的、哪些必须人来看、知道命令怎么敲。
> 配套文件：机器契约在 [AGENTS.md](../AGENTS.md)；写作规则在 [skills/fuben-write/SKILL.md](../skills/fuben-write/SKILL.md)。

## 第 0 章 · 先搞懂三件事

### 0.1 什么是「skill」

这里的 skill **不是代码程序**，是**写给 AI 看的说明书**：一个文件夹，里面有 `SKILL.md`（主文件）和 `references/`（细节分册）。AI 读到它，就按里面的规矩干活。

- 一个 skill 只干一件事（本仓库的 `fuben-write` 只负责「写稿」，`fuben-review` 只负责「审稿」）。
- `SKILL.md` 里那行 `description` 是**触发词**：用户说到「人生副本 / 剧本人生 / 口播稿」这类词，AI 才会调用它。
- `references/` 是分册，主文件里用链接指过去，避免主文件太长（规矩：主体超 500 行就往下沉）。

### 0.2 这个仓库干什么

生产**抖音「人生副本」第二人称口播剧本**：主播从头念到尾、观众不跳的那种逐字稿（默认全程用「你」）。

### 0.3 最重要的一句话

**v3.0 之后，机器不管「好不好看」。** 机器只做三类事：算数核对（数字有没有矛盾）、产物完整性（文件齐不齐、哈希对不对）、发布证据与数据台账。**「水不水、能不能爆」全部由提示词纪律＋人工审读判断**，并且必须落纸点名（引原句、给行号）。

## 第 2 章 · 全流程（AI 拿到题面之后的 8 个动作）

整体管线（AGENTS.md 里的原话）：

```text
00 简报 → 01 深读+检索(热帖热评 ≥8 路＋事实 ≥4 路，首批 ≥12 路)+选题三闸+方向卡(用户选定)
→ 02 人生时间轴(6–9站；事件/物证/人话/笑点；爽点四段；物证三栏；见证链)
→ 03 成稿(首行即钩+签名后置+钩子A/B/C同批+分块直写+块级三问+物证回收点名)
→ 04 投手预演七问+在场的人扫描+物证回收+接缝扫描+平铺扫描+念稿测试+账目手算+笑点扫描+十一项过线清单/五个自查问题
→ 04b fuben-review 读通专项 → 05 自检八问+技术核对 → 交付
→ （发布后）台账回传数据 → 下一代调参
```

### 阶段 0 · 读题与建目录（几分钟）

- **输入**：用户给的题面（如《天天去健身房但是偷吃的人》）。
- **产出**：`作品/NN_主题/_运行/YYYY-MM-DD/00_简报.md`。
- **写什么**：日期、题面原话、体裁、主角、观众关系预判、一句话主线（预填）、红线（无烟/不抹黑/不嘲笑/不报必爆）、发布合规（「剧情为虚构演绎」）。
- **为什么要有**：后面每一步都要回头对照「当初答应写的是什么」。

### 阶段 1 · 深读 + 检索 + 选题 + 定方向 → `01_深读_检索与方向.md`

**① 深读题眼**：谁在受这个处境的罪？观众为什么会说「这也是我」？看完想让他做什么动作（哭/骂/讲自己的事/转发）？

**② 真实搜索（硬承诺，不调用即失败）**：

- **定板前**：**第一批合计 ≥12 路**——**热帖热评层 ≥8 路**（贴吧/抖音/知乎/小红书/微博的热评热帖：找笑点机制、观众原话、名场面、情绪现场）＋事实/场景/数字 ≥4 路（同类人真实经历最重要 / 行业场景细节 / 数字与政策锚）。**检索（尤其热帖热评）占整个创作的 30–50%。**
- 逐路登记成表，一行不能少：`批号 | 检索词 | 来源（可回链） | 取用的真实骨架 | 用到哪一站`。「来源：某网」这种摘要不算数。
- **≥千元的关键数字必须单独占一路校验**，不许凭印象写大数。
- 检索结果**只许进「事件＋物证」**，不许排成介绍、不许让角色停下来科普。
- 外部素材里有吸烟等违规元素的：**素材是外部事实，但不进稿**。

**③ 定板后补检索（v3.0.1 强制，批号 `B<日期>-NN`，≥4 路）**：方向定了以后再跑一批，回答的是**另一个问题**——「这一版有没有人、有没有那句话说出口」。

- 定板前解决「题材真不真」；定板后解决「**人**」：主角身边谁在场、有没有原型锚可升级、有没有真实口吻可借。
- 进稿判据：只进「人 / 事件 / 物证 / 一句人话」；没补到合适的就如实写「本批未进稿」，不硬塞。
- 没跑这一批 → 这篇**不得标「可交付」**。

**④ 选题三闸（一票否决）**：

| 闸 | 问什么 | 不通过的后果 |
|---|---|---|
| 闸一 · 一句话主线 | 这是谁、他经历了什么、最后怎么了？ | 说不清＝毙 |
| 闸二 · 观众关系 | 爽（我也想这样）/ 共鸣（这也是我）/ 猎奇（我没见过且是真的），**必须写出证据句** | 写不出＝毙 |
| 闸三 · 情绪出口＋互动动作 | 看完想干什么？这个动作要在结尾互动钩里被点名 | 说不出＝毙 |

**黑名单**（命中即重做）：主角没有社会关系（或所有人都只活在转述里）／纯制度政策观察／只有流程没有阶段／灰到底无释放。

**⑤ 产出 3–4 张方向卡**：每张写「一句话主线、观众关系＋证据句、开场第一句（钩）、峰值放哪站、兑现认领（正文会出现的字面）、真实原型锚（可回链）、风险」。

**⑥ 交用户选定方向**——**没选定不许开写**。产物里必须有「方向定板」小节（用户原话或代选授权）。

> 技巧：写前按 `references/8_拆文库与对标.md` 三步查——**优先读近期拆解**（46／48a–c／00 合集本体）→ 只读 `情节节点.md`（峰值位置、每站字数）与 `写作手法.md`「可复用工艺」→ **抄 3 条手法＋1 条避坑**（每条带出处编号），记三个数当参考（字数、峰值位置、句均长度）。**借事实与结构，不借文本；不打分、不比分数。**

### 阶段 2 · 人生时间轴 → `02_场次单.md`

把人生（或一段关键人生）切成 **6–9 站（默认中档 1800–2600 字）**，每站四件套（v3.0.5 加「笑点/名场面」）：

| 每站必写 | 说明 |
|---|---|
| **事件** | 谁要什么 → 谁挡着 → 他做了什么 → **哪一格变了**（账目/关系/权力/信息） |
| **可视物证** | 这一站能拍到的东西（画面里可以没有人，但必须有这件物） |
| **一句人话** | 观众会跟着说出口的那句（写进正文，不是旁白解释） |

**结构骨架（爽点四段）**：压制 → 谷底（**全篇 60–70% 处**）→ 反打（**主角自己动手**）→ 释放（**写清对手输了什么**）。

- **钩点密度**：每 200–250 字换一次局面；**两钩之间 >300 字＝水段**，压或删。
- **物证 3 件**：1 件主物证走全篇并换义 + 2 件副物证；每件必须干活（被递出/退回/记账/摔/点破）。
  - **物证三栏（v3.0.3）**：每件写满 `第一次出现（站）｜换义点（站）｜**最后一次出现（站＋一句可拍动作）**`。最后一栏不许写「结尾出现」这种话，必须是正文里真会出现的那一句。
- **见证链（v3.0.2）**：释放那一站必须写一行 `谁在场 | 他在哪一句/哪个动作接住`。全篇除主角外没有具体的人，或人都只活在转述里 → 回选题。
- **谷底不许靠数字（v3.0.2）**：谷底那一下由人的反应造成（半句话没说完／沉默／放下筷子），数字放在谷底之前当条件。
- **伏笔 ≤3**（每个登记埋在哪站、哪站回收）；**判词 ≤2 句**。
- **兑现认领表**：`| 兑现点 | 认领关键词 |`——关键词必须是正文里真会出现的字（数字、器物名、原话）。
- **在场的人登记（v3.0.2）**：他首次出现行号 / 与主角同框的动作台词 / 删掉他释放还成立吗。

### 阶段 3 · 成稿 → `正文.md` + `03_初稿.md`

**先决三件事**：方向已选定；开场第一句已定；**钩子 A/B/C 三条同批写出**。

**开场规矩**：第 1 行就是钩（结果/冲突/反常/悬念四型）；「今天你要体验的人生副本是」**后置到第 2–3 行**；「系统提示」≤2 行且自带信息；**前 160 字内不许出现定义、科普、口径、身世交代**。

**节奏**：每 15–25 秒（≈70–125 字）翻一次面；中段禁信息真空；结尾＝金句（≤16 字）＋具体互动钩（提问/征集/立场，不写「你怎么看」这种空壳）。

**分块直写、防漂移**：一次只写一站（≤35 行），写完逐行回读，每站过**块级三问**并把答案写进 `03_初稿.md`：

1. 这一站之后，**谁的处境变了**？（答不出 → 并入别站或删）
2. 这一站给观众的**新信息/新坏消息**是什么？（「他很惨」不是新信息）
3. **删掉这一站，后一站还成立吗**？（还成立 → 它是装饰，压成一句判词）

**物证回收点名（v3.0.3，整篇写完后）**：三件物证逐件过三问，答案写进 `03`——

1. 它在正文里出现了吗（给行号）？
2. 它最后一次出现，是不是一句**可拍的动作**（不是名词复述）？
3. 删掉最后一次出现，后文还成立吗？成立＝它没干活，补动作或换物证。

**写法铁律（12 条，全部靠提示词自检）**：

1. **无烟**（用户红线，最高优先）：正文、短版、钩子三个文件各搜一遍「烟」，**0 命中才交**；外部素材有烟也不进稿。
2. **旁白驱动**：引语字数占比 ≤10%，每站 ≤1 句原话钉子，全篇钉子句 ≤8，禁「你说他说」乒乓回合。
3. **禁词/禁腔**：首先、其次、然而、随着、不禁、值得一提、眼眶一热、五味杂陈……（完整表在 `references/5`）；开头禁「先校准/先说说/今天我们来聊/大家好」这类定义腔。
4. **抽象只准翻译成身体、器物、数字**，禁情绪形容词宣布。
5. **口语短句成行**（5–12 字是语感指纹）；每段都能当分镜拍。
6. **账目（v3.0.2 收紧）**：**正文里不许出现一个算式**。数字只准四类用途——对比（一进一出）／事实（总数）／背叛（数字打脸）／动作（走四十分钟）；加减乘除与换算全部写进 04 后台手算表。判据：正文里任何一个数字，如果删掉它没人能反算某笔账，它就本该待在 04。

### 阶段 4 · 投手预演 + 返工 → `04_审读与返工.md`

**姿态**：假设你是这条稿子的投手（操盘手），平台只给你冷启动池几百次曝光。**每条都要引原句＋行号，答不出的地方就是返工点。**

**投手预演七问**：

1. 第 1 行／第 3 秒：观众凭什么不划走？钩是哪一型？签名句在第 2–3 行吗？
2. 第 15–25 秒：第一个翻面在哪？
3. 第 60 秒：还在推进吗？**最早的划走点在哪一段**？
4. 谷底（60–70% 处）：最疼的一下是什么？是动作造成还是旁白抒情？
5. 反打/释放：主角自己做了什么？**对手当场输了什么**？**谁看见、谁接住**（台词/动作＋行号）？——三项缺一，释放只算半个。
6. 结尾：凭什么点赞评论转发？互动钩哪一句？金句在哪？
7. 观众关系：哪一句兑现了它？

**五道人工关卡**（全在提示词里，没有脚本）：

| 关卡 | 干什么 |
|---|---|
| **在场的人扫描**（v3.0.2） | 数一遍除主角外还有几个具体的人：`称呼｜首次出现行号｜同框动作台词`；少于 1 个＝平淡警报 |
| **物证回收核对**（v3.0.3） | `物证｜出现次数｜行号｜最后一次出现是不是可拍动作`；出现 <2 次或最后只是名词＝没回收 |
| **平铺扫描** | 找连续两段以上只展示、没有局面变化的段落，给行号＋字数＋占比；处置三选一：压成判词／并进有对手的站／写明保留理由 |
| **可删测试** | 划掉它，后文还成立吗？成立＝装饰 |
| **念稿测试** | 出声读一遍，拗口立刻断行；两口径估时（语感 4.5–5 字/秒；机检 6.4 字/秒）；连续 30 秒纯介绍/回忆/抒情＝断崖点 |
| **接缝扫描**（v3.0.4） | `接缝位置（站 N→N+1）｜上一站尾行｜这一站首行｜接法（因果/转折/时间/物件）｜顺不顺`；不顺的当场改首行 |
| **账目手算** | 正文每个数字主张抄进表里反算：`行号｜主张原文｜算式｜结果｜是否一致`；先搜一遍运算字眼，正文在做运算就说明该搬进表 |

**打分**（按 `references/7_自检与评分.md`）：

- **十一项清单**（每项 0–2 分，满分 22；v3.0.5 新增第 11 项「笑点/名场面」）：三秒钩／一句话主线／观众关系／翻面节奏／谷底／反打与释放／物证三件／语言／账目／结尾／笑点。**18 分以上可交付，任何一项 0 分不得交付**（笑点项要求：每站 ≥1、全篇 ≥8、谷底 0 个、同一个梗要升级）。
- **五个自查问题**（v3.0.4：**不打分**）：**开**（前 3 秒凭什么不划走）／**拉**（中段哪一下让人停不下来）／**反**（有几个反转、有没有一次说透）／**节**（有没有「再举一例」的段落）／**尾**（凭什么点赞评论转发）。每问引原句＋行号，给「过／不过／怎么修」。
- **拆文库不打分**：那些分数是别人拆解时的单次读书笔记（见 references/8 第一节），只作手法参照——写前抄的 3 条手法＋1 条避坑，写在 04 的「参照记录」里（用在哪一行／未采用＋原因）。
- 写下分数＋证据行号＋返工项。

**分层返工**（哪一步的问题退回哪一步）：选题/观众关系空 → 回阶段 1；站并列/没谷底/反打靠旁人 → 回阶段 2；开场不钩/水段 → 回阶段 3；只有用词断句问题 → 局部改。**改完必须重新自检一遍并写进 04，不凭「我改了」通过。**

### 阶段 4b · 独立审读 → `审核报告.md`（skill：`fuben-review`）

按 `skills/fuben-review/SKILL.md` 走两条线：

- **创作审查**：追看欲、兑现有没有演出来、伏笔与侧面描写有没有效。
- **读通专项（16 条）**：标题承诺与事件是否吻合／物件食物人物有没有漂移／时间线接不接得上／代词指代／问答有没有回应关系／序列词一致／连接词承诺的递进转折成立／计数主张准确／专业术语与角色自白别混／转折有没有人物支撑／改稿有没有残留旧设定／**账要平（人工手算）**／**开头 3 秒体检**／**正文零算式**（v3.0.2）／**见证链**（v3.0.2）／红线复扫。

**报告必须写**：`body_path` ＋ `body_text_sha256`（正文 SHA-256），结论分「确定错误 / 待确认 / 可接受表达」。审读分 solo 自检与独立会审两种，**不许冒充多 Agent 会审**。

### 阶段 5 · 自检与交付 → `05_自检.md`

**先过提示词八问**（逐项给行号或数字）：

1. 第 1 行是不是钩？签名句在第 2–3 行？前 160 字有没有定义腔？

3. 每 15–25 秒有没有翻面？有没有 >300 字水段？
4. 结尾有没有金句＋具体互动钩？
5. 无烟搜了三个文件吗（0 命中）？
6. 禁词表逐条扫过吗？
7. 账目手算对得上吗？
8. 十一项清单几分（满分 22）？低于 18 分的项返工到哪一阶段？笑点项每站都有吗？

> v3.0.3 追加：**物证回收点名**的结论（三件 YES/NO＋行号）也要写进 05。

**再跑技术核对（脚本唯一的位置）**：

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --json                 # 输入/算术/指标

```

- `BLOCK` 只可能是确定的输入或算术错误——必须清零；`REVIEW/NOTE` 是描述信息，由人判断，可以「保留＋写明理由」。
- **PASS 只说明没有机械错误，不是创作批准。**

**交付包清单**：`_运行/YYYY-MM-DD/` 下 `00_简报 … 05_自检.md`；根目录 `正文.md`、`钩子备选.md`、`审核报告.md`。可选：`正文_短版.md`（重写不是删减）、`分镜建议.md`。

## 第 3 章 · 49 项测试是什么

测试文件：`tests/test_fuben.py`（602 行，纯 Python、不调用任何模型、不联网），跑法：

```bash
python3 -m unittest discover -s tests -q     # 只跑测试
python3 scripts/test_gates.py                # 体检总入口：测试 + 受保护语料哈希
```

**它们是什么**：**软件不变量测试**——用来保证「工具本身不会算错、不会误判、坏了能报错、旧结论不会污染新稿」。**它们不判稿子好不好看**（文件头就写明：测试通过不代表稿子好看）。

49 项分六组：

| 组 | 数量 | 管什么 | 典型用例 |
|---|---|---|---|
| **NumberTests** | 3 | 中文数字解析 | 「两万八」能解析成 28000；口语歧义（「俩」）必须显式开启；数字残缺时**绝不猜**第一位 |
| **EngineTests** | 22 | 核心引擎：输入边界、显式算式与字数主张、哈希绑定、严重度 | `12×3=36` 对/错分别判绿/红；除零是 REVIEW 不是崩溃；「五位数」这类位数主张要核对；引文边界不能被空格绕过；空标题/二进制文件/缺文件都报错不崩；**审核报告必须绑定当前正文的路径与哈希**（旧报告给新稿背书＝失败）；时间线/语义连续性这类判断**不许被机械定罪**（保持 REVIEW 由人裁定） |
| **RouteTests** | 10 | 仓库不变量：路由与部署一致性 | `AGENTS.md` 路由表覆盖当前所有作品；`skills/*/SKILL.md` ↔ `deploy-antigravity-skills.py` 的 `KNOWN_SKILLS` 清单一致；分发出去的多份拷贝逐字节一致；提示词模板不许偷偷加回「创作配额」；hook 流程不强迫 fuben 走通用小说风格清理；工具在源码目录之外也能独立部署 |
| **ProductsTests** | 1 | 产物完整性 | 缺 `_运行/` 目录时报告 **MISSING**，而不是当 PASS |
| **ReleaseTests** | 7 | 发布证据链 | 没有证据时只能标 PROVISIONAL，不能当已发布；改了正文又刷新清单**不能洗白**旧审核；改设定/改媒体/改审核哈希都该 BLOCK；媒体工具失败不能算「估算通过」 |
| **DataTests** | 6 | 数据台账 | 台账 schema 严格校验；观看比例 ≠ 完播率；写入原子化、可重复执行（幂等）；台账损坏时**失败关闭**（不猜）；旧格式迁移保留原始值、绝不猜错位行；危险的老命令会被拒绝且不改数据 |

外加 `scripts/test_gates.py` 会同时校验 `tests/protected_sources.json` 里**拆文库原文的 SHA-256**——`拆文库/*/原文/*` 是「校准规则用的原始语料」，**不许改写、不许删除**；要加新源必须显式更新清单（不能跳过枚举）。跑通输出 `SOFTWARE-AND-SOURCES: PASS`。

**一句话**：49 项测试保证的是「**工具的地基不会塌**」，不是「你的稿子好」。稿子的好坏由 04/05 的人工判断和真实数据负责。

## 第 6 章 · 常见问题（FAQ）

**Q1：49 项测试全过，是不是就能发了？**
不是。测试只管工具不出错。能不能发看：**选题四关＋剧本五关先过**（v3.1／v3.3）、十一项 ≥18 分且无 0 分项、审核报告绑定当前正文哈希、无烟 0 命中、发布建议带了虚构声明。

**Q2：我改了正文，为什么 `fuben_products` 报 MISSING？**
因为 `审核报告.md` 里绑的是旧哈希。**改了正文必须重出审核报告**（重跑 04b），这是防「旧结论给新稿背书」。

**Q3：为什么稿子里不能算账？账目不是要能反算吗？**
账目要能反算是给**后台**的要求（写在 04 的手算表里），不是给**观众**的。口播是按秒走的，观众听见「先减后除」那两秒，注意力就从人身上挪到数字上了（88 的教训）。

**Q4：为什么一定要有「见证的人」？**
因为「自己在家偷偷完成」的释放，观众感受不到「有人知道也没事」——这正是 88 v1 被判「平淡」的根因。见证链不等于加戏，前台一句话、老哥一句「我给你看着」就够。

**Q5：允许我偶尔破一次例吗？**
允许，但**必须写明理由并留在文件里**（例：对照篇的 2 条 REVIEW 计数提示，人工核实边界后判定「保留，不修」）。这个仓库不搞机械清零——但「保留」也要落纸。

**Q6：拆文库有五维分数，为什么不拿来对标？**
因为那是 `story-short-analyze` 的 Stage 6 产出：**单人、单次、附一段文字说明**（没有多评委、没有评分细则），对象还是网文短篇（1.2k–4.5k 字），而我们的稿子默认 1800–2600 字口播（v3.0.5）——文体、介质、时长都不同。拿它当分数，等于把别人的读书笔记当自己的考试成绩。**正确用法**：读近期拆解的手法，抄 3 条＋避坑 1 条，带出处编号。

**Q7：为什么要分块写？块与块会不会不顺？**
分块（一次一站 ≤35 行）是**写作过程**的防漂移手段，不是交付格式；不顺手的情况都来自「各站分别起笔」——所以补了**接缝三要件**（首行接住上站尾行／禁两站同式起笔／场景连拍共享主语时空）和**整篇连读**。行业做法也一样：脚本用「阶段｜口播｜画面」表格，接缝靠固定件、递进抛点、显式转场列，不是靠感觉。

**Q8：这套流程 100% 保证出爆款吗？**
不保证，也不允许这么说。唯一被验证的是：**规则能稳定产出结构达标的稿子**（对照篇初稿即满分，零新规则返工）。真实出池率要等发布数据回传。
