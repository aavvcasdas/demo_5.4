# Skill 诊断与优化 · 2026-09-23

> 问题：人生副本 skill 生成的稿子「没有笑点、没有剧情、没有感同身受、没有钩子、没有侧面描写」。
> 本轮做的三件事：**① 定位病因（带仓库内证据）② 按四个参考项目重建手艺层 ③ 修好断掉的执行链**。
> 参考项目全部本地克隆后逐文件读，没有用网页搜索代替读源码：
> `0xsline/short-drama`、`blader/humanizer`（51.6k★）、`hardikpandya/stop-slop`（17.5k★）、
> `anthropics/skills`（官方，含 skill-creator 与 agent-skills-spec）、`Leonxlnx/taste-skill`（89.5k★，参考其「反 LLM 默认值」思路）。

---

## 一、结论先说

**你的稿子奇怪，不是因为规则太少，是因为规则里没有「形状」。**

现行执行链一共 42,524 字，其中**真实例句的数量是 1 处**（而且那处还是文件名引用）。
同一个仓库里躺着 **53 万字**的 `写作手法.md`、**107 万字**的 `情节节点.md`、**350 万字**原文——
全部拆好了、标好了手法名和字数位置，**没有一条被现行 profile 引用**。

对照四个参考项目，差距非常具体：

| 项目 | 它的规则长什么样 | 本仓 v13 的规则长什么样 |
|---|---|---|
| `0xsline/short-drama` | 5 种钩子 × 每种 5 个子模式 × **每个子模式一段可直接抄的剧本** ＋设计要点＋致命问题清单＋自检表（`hook-design.md` 里 63 处引用示例） | 「钩子带动下一步，不是一直欠账」（1 句，0 例） |
| `blader/humanizer` | 25 个 pattern，每个都是 **Watch for → Problem → Before → After**，93 处 Before/After；还有一节 **When not to act** 列出「哪些人味不许清掉」 | 「删的是断掉主线的重复和闲笔，不是所有慢句」（1 句，0 例，无保留清单） |
| `hardikpandya/stop-slop` | 结构级清单：binary contrast / dramatic fragmentation / **false agency** / narrator-from-a-distance，每条给 Pattern → Problem → Instead，配 `examples.md` 的 Before/After | 无对应内容 |
| `anthropics/skills`（skill-creator） | Progressive disclosure 三层：metadata → SKILL.md（<500 行）→ bundled resources **按阶段加载**；「Reference files clearly from SKILL.md **with guidance on when to read them**」 | 有分层意识，但**加载表缺失**，且真正该分层的语料没有变成 resource |

模型不会从「要有钩子」学会写钩子。它会从「悬念钩：他缓缓摘下面具——【本集完】」学会写钩子。
**v13 把配额删对了，把示例也一起删错了。**

## 二、六条病因（每条都有仓库内证据）

### 病因 1：手艺语料没有被接进执行链（根因）

- `人生副本实录.md`（v13，39 行）只说「读本题相近的真实原文，不只看拆解摘要」。
- 全仓唯一一处指向语料的链接在 `人生副本_通用骨架.md` 最后一行（「可对照 `拆文库/17_.../原文.txt`」），
  而那个文件自己声明「不是填表模板。**只在卡住时读**」。
- `reference-index.md`、`人生副本_Agent方法.md`、`fuben-review/SKILL.md` **一次都没提 `拆文库/`**。
- 结果：`作品/79/_运行/00_简报.md` 的「已加载」清单只有三个文件——profile、Agent 方法、story-architect 模板。
  **没有一篇语料。**

**最能说明问题的一条**：`_系列总拆书.md` 结语那三句话——
> 「把抽象的焦虑翻译成身体、器物与数字；把人生的下坠铺成清单与编年；把清算留给一个最小的单位
> （一碗面／半步／一秒／68块5）。」

**这就是「感同身受」的引擎本身**，而它只存在于总拆书的结语和已归档的旧配额包里。
现行 profile 一个字没引。用户抱怨「没有感同身受」，病因就在这里。

---

### 病因 2：已作废的配额包被 glob 顺手加载，稿子是照着死规则写的

`人生副本实录_v1_归档.md`（54KB）和现行 profile **放在同一个 `genre-styles/` 目录**，
而 `story-short-write/SKILL.md` 与 `reference-index.md` 都写「按题材加载 `genre-styles/{题材}.md`」——
任何按目录列举的动作都会把它读进来。

**实证**：`作品/80_练薄肌的人活在成都/_运行/03b_审读.md` 与 `07_诊断_流水账.md` 全篇按这些条款验收：

> 「场景 4（火锅／麻将／天台评论／麻辣烫）＋编年 1＋收束；麻将 24 行、麻辣烫 26 行，达最小拍子。」
> 「时间标签 7 个，喜剧支线豁免线 ≤12 内；数字全部绑动作。」
> 「内联说话 ≥15 行；梗引用从 11 压到 6。」

**这些条款（§17.1 最小拍子 / §17.2 全篇配额 / 时间标签≤6 / 内联说话≥15行 / 场景≥4 每个≥25行）
只存在于归档包里**，现行 v13 里没有。审读按一套不存在的规则判了「达线」，
用户看完仍然裁定「看不懂、是流水账」。

这就是典型的 Goodhart：**指标全绿 ≠ 好看**。而 `scripts/fuben_policy.json` 早就把
`creative_rules` 全部置为 `null`、`metric_thresholds: "descriptive_only"`——
文档层的决定和实际执行层的行为**互相矛盾**。

---

### 病因 3：喜剧模块完全缺失

- v13 profile 里「笑点／搞笑／喜剧」**零次出现**。
- `genre-styles/沙雕脑洞.md` 是**短篇小说包**（第一人称吐槽体、弹幕、系统流、快穿），
  而 `story-short-write/SKILL.md` 明确写副本分支「不继续加载下方普通小说 Reference Gate……题材包」。
- 所以写「偏搞笑」的题时，模型手上**没有任何笑点机制**。它只能做一件事：把检索到的热梗原句搬进正文。
- `作品/80/_运行/07_诊断_流水账.md` 自己写出了病因：
  > 「我把『梗的出处清单』当成了剧本——**检索材料被摆进正文而不是被炖进因果**。」

而语料里明明有一整套喜剧机制躺着没人用：
17 号的「沉默授权／归因反转／请君入瓮／静物化余波／对照组装置／受辱的精确剂量」、
29 号的「迷因即设定／急了学（自欺闭环）／对手的最小出场（十一个字反派）／双假峰＋一真谷」、
32 号的「递归正义／声音的工程学描写／议论句限量供应」、39 号的「假机构道具学／现实入侵法」。

---

### 病因 4：执行链断裂——`arena.runtime.json` 与 `AGENTS.md` 不存在

- profile v13、`人生副本_Agent方法.md` §0、`story-short-write/SKILL.md`、`story-long-write/SKILL.md`
  四处都硬性要求：正文必须由 `arena.runtime.json` 定义的执行通道产出，
  **「两者都不可用就停止正文产出并报告阻塞」**。
- 实际仓库根**没有** `arena.runtime.json`，也**没有** `AGENTS.md`。
- 但它们**曾经存在**：`作品/79/审核报告.md` 写「arena.runtime.json v1.1.0」，
  `_运行/00_简报.md` 写「v1.3.0」，`作品/80/审核报告.md` 写「v1.2.0 全管线」；
  同一份报告还披露了事故：「本轮中途沙箱被整体回滚为 base 克隆」。
- `docs/Arena运行时.md` 的第 3 行就是一个死链：`[arena.runtime.json](../arena.runtime.json)`。

**后果**：按规则应该 `BLOCKED` 并停下，但用户要稿子，于是实际发生的是**静默兜底**——
主会话读完规则直接写，既没有角色分工也没有阶段产物约束。
「文章怎么这么奇怪」的一部分答案就是：**它是在一条被明确禁止的兜底路径上生成的。**

---

### 病因 5：当前交付稿违反本仓三条自己的契约（可复现）

对 `作品/80_练薄肌的人活在成都/正文.md`（用户手上那一版）实跑：

```
$ python3 scripts/fuben_run.py 作品/80_练薄肌的人活在成都/ --profile full
MECHANICAL: FAIL | profile=full
BLOCK SCOPED_CHARACTER_COUNT L213: “人生就两字”只计其后短语；该短语有 4 个汉字，不是 2 个
```

1. **机检 BLOCK**，而 `审核报告.md` 写的是「机检 V3：PASS，exit 0，BLOCK/REVIEW 双零」——证据已过期且未声明。
2. **审核报告缺 `body_path` 与 `body_text_sha256`**，违反 `fuben-review/SKILL.md` §4；
   `fuben_loop.py review` 实测报 `MISSING_REVIEW_BODY_PATH` + `UNBOUND_REVIEW_REPORT`（79 号同样）。
3. **最刺眼的一条**：本仓的回归红样
   `作品/_regression/80_练薄肌的人活在大耍起时代_红样/正文.md`
   结尾与交付稿**逐字相同**（「你没理他们 / 认真回了九个字 / 人生就两字 / 练完再耍」），
   并触发同一个 BLOCK。
   **也就是说：仓库自己已经把这一版稿子的结尾固化成「这是失败样本」，而它同时是交付稿。**

顺带查出两个测试长期红着（本轮已修，见 §四）：
- 绿样夹具的 `body_path` 写的是作者本机 Windows 绝对路径，`_normalize_report_body_path` 直接 `resolve()`，
  在任何别的机器上恒判 `STALE_REVIEW_BODY_PATH` → `test_regression_work_80_red_and_green_fixtures_cover_current_scope` 长期失败。
- `test_old_unsafe_record_command_rejected_without_data_mutation` 去哈希两个**未入库**的本机 CSV → 恒 error。

---

### 病因 6：过程税过重，注意力预算被流程吃掉

阶段 01 的硬性要求（`人生副本_Agent方法.md` + `docs/Arena运行时.md`）：
深度理解主题 → **≥8 路并行真实搜索**（不调用即任务失败）→ 逐条记录检索词/批号/来源/质感 →
产出 3–4 个分类型方向 → 等用户选定 → 才准动笔；之后还有 03 审读、04 返工、04b 读通专项 11 条、
05 机检、哈希绑定、关联依赖检索。

对照 `anthropics/skills` 的 skill-creator 指引：
> 「Prefer a short, clear instruction over another exception or repeated explanation.」
> 「Try to explain to the model **why** things are important in lieu of heavy-handed musty MUSTs.」

本仓的 v13/v14 之前的文本里，「必须／不得／一律禁止／铁律」的密度极高，
而**「为什么这样写观众才会留下来」的示范为零**。
模型把预算花在满足流程上，就没有预算去写戏。
80 号的 02b→02c 三轮返工全在处理配额与勘误，没有一轮在处理「这场戏好不好笑」。

## 三、四个参考项目分别借了什么，接到了哪里

### 3.1 `0xsline/short-drama`（12 文件，SKILL.md 520 行 + 8 个 references）

**它做对的核心**：每个 reference 都是「类型表 → 子模式表 → **一段可直接抄的剧本** → 设计要点 → 强度分级 → 自检表 → 致命问题清单」七件套。
`hook-design.md` 5 种钩子、`opening-rules.md` 6 种开场模板、`satisfaction-matrix.md` 5 大爽点、
`villain-design.md` 4 层反派、`rhythm-curve.md` 单集微结构 + 四阶段波形。

**本仓采用**：

| 它的东西 | 接到哪里 |
|---|---|
| 6 种开场模板（每型带剧本示例） | `fuben-craft/开场与钩子.md` §六种开场模板——保留分类法，示例全部换成 `拆文库/` 的真实口播原文（02 倒计时压迫 / 15 数字判词前置 / 13 基线定价 / 17 热词翻转 / 28 结果先行 / 38 反常物） |
| 5 种钩子 + 子模式 + 叠加规则 + 分阶段配置 | 同文件 §段内钩子五型。**关键改造**：短剧可以把钩子押在片尾，口播没有下一集，所以改成「每 200–400 字挂一个段尾钩子」，并给出单条内的分布形状（主兑现置 75–88%，与 `_系列总拆书.md` §十的「反转置 80–85%」对齐） |
| 爽点＝压抑→释放；强度分级；致命问题清单 | `fuben-craft/爽点兑现.md`：压成单条口播的四拍（蓄势／加码／兑现／余波），**明确指出「加码」是最常被跳过的一拍**；五种兑现型换成语料实测型（原话奉还／证据反杀／请君入瓮／归因反转／**钝刀断线**） |
| 反派三原则（可恨／可信／递进） | 同文件 §对手设计。可恨的手段改成语料里的**话术工具箱**（道德绑架、为你好式 PUA、「青春期都这样」的系统性怠误、雌竞投名状、音量的心虚学） |
| `/review` 五维打分表 | `fuben-craft/口播腔调与反AI味.md` §D + `fuben-review/SKILL.md` 的五维（追看／笑点／共情／兑现／腔调），**并加了三条防 Goodhart 纪律**：每分必须挂原句、总分不作为通过证明、不许为刷分塞料 |
| rhythm-curve 的加速／减速手段表 | `fuben-craft/结构与曲线.md` §节奏调控，保留它最好的一句判据：「喘息段是否也在推进剧情？（不能只是闲聊）」 |

**没有搬的**：付费卡点（`paywall-design.md`）、50–100 集分集目录、出海模式。
口播单条不吊跨集胃口——这一点 v13 已经写明，本轮保持不变。

### 3.2 `blader/humanizer`（51.6k★，SKILL.md 单文件 25 patterns）

**它做对的核心**：
1. **四段式**：Watch for → Problem → Before → After，93 处对照。
2. **按强弱排序**：§1–§5 见一次就改，标 *weak alone* 的要同段有其他 tell 才动手。
3. **给出「为什么 AI 会这样写」的机理**（模型选最可能延续的、面向最广读者的默认项；人类为特定读者做不均匀的具体选择）——所以规则可以泛化。
4. **When not to act**：明确列出「哪些人味必须保留」（具体怪细节、矛盾情绪、年代梗、真诚的旁白插入）。
5. `AGENTS.md` 里写明改版纪律（pattern 不重复、编号连续、三处版本号同步、发布前跑 validator）。

**本仓采用**：

| 它的东西 | 接到哪里 |
|---|---|
| 四段式 + 强弱分级 | `fuben-craft/口播腔调与反AI味.md` §B：12 条中文口播 slop，前 5 条 strong（口号收尾／抽象总结代替戏／假动作主语／梗原文搬运／术语无解释），后 7 条 weak |
| §2 one-line closers / dramatic fragments | → §A 行节奏 + §B6：「你忘了 / 最难的 / 是你的朋友」被判为中文版的 dramatic fragmentation，给了两种改法 |
| §1 not X but Y | → §B11，**并保留了 humanizer 的例外条款**：负面半句纠正观众真持有的信念时合法。80 号的「薄肌 不是瘦」写在备忘录里、后面被评论区「哥 你那叫瘦」爆破——判定为合法 |
| §17 inflated verbs | → §B2「抽象总结代替戏」，配 80 号真实反例 + 三轮降档的改法 |
| **When not to act** | → §C 保留清单（本仓最缺的一块）：方言俚语、故意答非所问的玩笑、角色的自我辩解与胡诌、真实的重复口头禅、具体怪数字、矛盾情绪、年代梗。**并引了 80 号审读里两个本来就正确的裁决**（保留「羽化登仙」、保留「让人吃口鱼」）当范例，防止下一轮把它们清掉 |
| 「一个 tell 的分量与『认真写作者故意这么写的概率』成反比」 | → §C 总纪律 + `fuben_craft_scan.py` 的 strong/weak 分级与降级逻辑 |
| Mark → Draft → Check → Final 工作流 | → §E 改稿顺序三步（结构兑现 → 场面侧面 → 腔调），并指出最常见的错误是把第三步当第一步做 |

### 3.3 `hardikpandya/stop-slop`（17.5k★，SKILL.md + phrases/structures/examples）

**它做对的核心**：它管的是**结构级** slop，不是词表。
`structures.md` 的六类——binary contrast、negative listing、**dramatic fragmentation**、rhetorical setups、
**false agency**（无生命物做人的动作）、**narrator-from-a-distance**——每类给 Pattern → Problem → Instead。
外加「Cut quotables. If it sounds like a pull-quote, rewrite it.」和 5 维评分（<35/50 revise）。

**本仓采用**：

| 它的东西 | 接到哪里 |
|---|---|
| false agency | → §B3 假动作主语：「评论区炸了」「气氛凝固」「沉默蔓延」。改法直接引用语料的正解——17 号静场给的是**三种具体躲避动作 + 知了都停了**，而不是「空气突然安静」一句 |
| narrator-from-a-distance（「Put the reader in the room」） | → §B10 旁白讲解员 + `侧面与共情.md` §第二人称的三种用法（租用／被点名／受审），并明确禁止「你」变成解释概念的讲解员 |
| Cut quotables | → §B1 口号收尾（**最强的一条**），配 `_速拆卡.md` 的实证：「结尾 3 分区＝直白兑现无余味（警世与软文收尾说教税）」，改法是器物／动作收束 |
| telling instead of showing | → §B2 + §B7 情绪播报（改法：过身体／器物／数字三通道；正例用 80 号自己写对的「揣得很轻 跟做贼一样」） |
| Two items beat three | → §B6 排比三件套（weak，例外是第三拍翻面） |
| 5 维评分 <35 revise | → §D 五维评分，改成追看／笑点／共情／兑现／腔调 |

**没有搬的**：「Kill all adverbs」「No em dashes」「句子不许以 Wh- 开头」——这些是**英文散文**的规则，
中文口播的副词与语气词是人味的一部分（「嘛」「呗」「倒是」），照搬会误伤。
这一点在 §C 保留清单里明确反向写清了。

### 3.4 `anthropics/skills`（官方）

**它做对的核心**：`skill-creator` 的 Progressive disclosure 三层模型
（metadata ~100 词常驻 → SKILL.md body <500 行 → bundled resources 按需），
「Reference files clearly from SKILL.md **with guidance on when to read them**」，
「For large reference files (>300 lines), include a table of contents」，
「Domain organization: organize by variant，Claude reads only the relevant reference file」。

**本仓采用**：
- 新建 `references/fuben-craft/` 作为**第三层 resource**，8 个文件，每个 <300 行、带目录。
- `人生副本实录.md`（v14）与 `AGENTS.md`、`arena.runtime.json`、`人生副本_Agent方法.md` §2
  都给出**「何时读哪个」的加载表**，而不是一句「参考资料见目录」。

## 六、一句话总结

**旧 profile 告诉模型「要好看」，新 profile 告诉它「好看长这个样子，出处在第几篇第几行」。**
配额删掉是对的，删掉配额时把 500 万字已拆好的语料一起留在门外，是稿子变奇怪的直接原因；
`arena.runtime.json` 丢失导致的静默兜底，是第二个原因；
而本仓自己的红样夹具早就把这一版结尾标成失败样本——**工具链其实一直在报警，只是没人把报警接到创作层。**
