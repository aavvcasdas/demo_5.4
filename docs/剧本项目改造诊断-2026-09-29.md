# 剧本项目改造诊断 · 2026-09-29

## 结论先行

这个仓库之前把三件事混在了一起：

1. **人生副本口播稿**：旁白从头念，第二人称、数字、物件和叙述者拆穿都可以成立；
2. **拆文研究**：读取 ASR 原稿，提取“它为什么能推进”的机制；
3. **可拍摄剧本**：人物在场景里有目标、阻力、行动和结果，镜头/演员/声音可以执行。

`fuben-write` 的 v2.0 把第 1 件事做成了很重的表格管线，却被用户要求的“改成 Arena skill 剧本项目”打断。现在的改造不是把名字从“正文”换成“剧本”，而是把当前入口改成 `arena-screenplay`，把旧口播产线降为 legacy，并把审核从“自报全绿”改成“机械层 + 编辑层分离”。

## 读到的最新稿：87 为什么会长成这样

对象：`作品/87_年卡洗澡空调饮用水/正文.md`，617 字；对应 `_运行/2026-09-29/` 的 00–05 产物和 `审核报告.md`。

### 它做对了什么

- 首句“你把健身年卡用成了三个家电”有反常错位；
- “没有热水→办卡→三件套→限时→算账”能让人迅速理解题面；
- 第二人称、短行和几个现场问答适合口播；
- 999、320 次、5450 等数字可以作为素材，不是凭空出现。

### 它为什么仍然奇怪/不像剧本

- **无持续欲望**：主角没有一个贯穿的当下目标。是想解决洗澡？想把卡用回本？想说服店长？文本在三个目标之间来回切换。
- **无有效对手**：销售、教练、店长都只说一两句，之后让开；“淋浴限时十五分钟”本来能形成一场谈判，却被一句“第二天去算账”跳过。
- **事件是清单，不是戏**：洗澡、空调、饮水、教练、小哥、通知、榜单各自出现，几乎不改变下一步选择。与拆文原稿的“行动造成代价”相比，它是在说明“我把三种功能都用到了”。
- **反打没有发生**：`999 ÷ 320` 是作者/报告的计算，不是主角在冲突中拿来改变对方决定的筹码；店长“会籍都没算过”只是反应，不是规则、价格或关系的改变。
- **结尾是总结/CTA**：“别人办卡是为了练出腹肌”“活得像个人”“评论区报个数”都是作者盖章或发布运营，不是故事后果。
- **真实素材喧宾夺主**：18 路搜索和 8 个笑点逐条列在审读报告里，反而暴露了“研究数量代替戏剧判断”。搜索来的每个梗都想进正文，所以笑点密度上升，人物关系却没有升级。
- **口径自相矛盾**：报告说“1–2 分钟”，又用旧的 `[2800,3300]` 长篇参考带生成 `VOLUME_OFF_BAND`；617 字的短稿不该被旧小说体量规则反复解释，更不该用“用户授权”把工具噪声包装成闭环。

因此，87 可以保留为“口播段子样本”，不应标成 Arena 剧本。若要真正剧本化，应该把通知日写成一场：主角拿记录来谈、店长拿成本/合同来挡、双方行动后规则或关系发生可见变化；其余“接水/吹空调”只保留能服务这场冲突的动作。

## 旧审核脚本为什么奇怪

### `scripts/fuben_viral.py`

它读取的是 `02_场次单.md`、`01_深读_检索与方向.md` 等阶段文档，数“物证”“兑现认领”“检索路数”“评论区”等关键词，输出 9/9。它没有读取并理解人物目标、阻力、行动和结果，因此“9/9”只能翻译为“阶段卡片里写了 9 项”，不能翻译为“这条视频会火”。

### `scripts/fuben_claims.py`

它把阶段卡中作者预先写的认领关键词，与正文的字面出现做对表。`五千四百五` 在正文出现，不代表这一笔账在戏里产生了后果；关键词存在性是确定性检查，但它不是兑现质量。

### `scripts/fuben_craft.py` / `fuben_run.py`

它们对历史口播稿有价值：禁词、烟草红线、算式、哈希、格式和某些候选句式可以机械核验。但它们会产生几个误导：

- 617 字短稿落入旧长篇 band，却用 policy 授权解释成 NOTE；
- 小于 800 汉字时对白统计按设计归零，报告又人工自报“6 拍”，两套口径并列而不互相校验；
- style 候选、`PASS_WITH_REVIEW`、`VOLUME_OFF_BAND` 混在一个“审核报告”里，读者很难看出什么是阻断、什么是机器提醒、什么是人读判断；
- `PASS` 容易被生产者当成创作批准。

### 审核报告的问题

87 报告是主会话同时写稿、审读、写报告，里面有“笑点 8 处”“18 路检索”“结构 9/9”等自证字段，但没有一位真正独立的审读者，也没有引用“最早划走的具体段落”并给出返工。它满足了产物门禁，却没有把正文当成观众实际会听到的文本来对抗。

## 拆文原稿实际教了什么

### 《无辣不欢的一生》

原文路径：`拆文库/01_无辣不欢的一生/原文/原文.txt`。

它不是把“吃辣”相关素材列一遍，而是让每次选择同时带来奖励和代价：被激将吃变态辣 → 被喊“辣王” → 排骨汤尝不出味 → 腹泻 → 三天后自行回去加码 → 37 个小米辣/同城榜 → 医生警告和母亲撇红油 → 急诊 → 白粥回甘 → “微辣”。单个物件（汤、玻璃瓶、粥）在后面改变意义；最后的微小动作完成前文积累。

### 《外卖员的一生》

原文路径：`拆文库/02_外卖员的一生/原文/原文.txt`。

8 个“集”是 8 次权力位置变化，而不是 8 个行业资料块：取消订单/罚款 → 抢单 → 调度 → 封禁 → 算法收紧 → 事故和替罪羊 → 手铐/债务 → 新人注册。`系统故障` 和 `系统升级` 是回旋镖，`蓝色耗材` 从定义主角到反噬主角。台词很少，却每句改变了称谓、权力或预期。

### 与 87 的差异

拆文原稿中，细节是角色选择的证据；87 中，细节多是作者证明“我真的搜过/我真的把三件事写齐”的证据。前者会把主角推到下一步，后者只把题面讲完整。

## 抖音搜索结果与本项目的采用边界

本轮搜索日期：2026-09-29。

- 抖音创作者中心：<https://creator.douyin.com/>。发布后数据应从实际创作者中心回填，不采信网上统一“及格线”。
- 新榜 2026-08-26 访谈“剧本人生”：<https://news.qq.com/rain/a/20260826A0DBMC00>。报道提到该账号从虚构猎奇转向真实普通人经历，评论区出现“这是大部分普通人的一生”式共鸣。可借鉴的是具体普通人的生活和评论参与，不是照搬账号数字或承诺流量。
- 抖音搜索公开文稿页：<https://www.douyin.com/shipin/7316056034525874186>。固定句“今天你要体验的人生副本是”是系列入口，但入口不等于一篇好稿；后面仍要靠事件和状态变化。
- 公开口播教程：<https://xiangyugongzuoliu.com/douyin-xiaohongshu-popular-creation-methods/>。其中“黄金 3 秒、每几秒一个信息点”等属于经验性建议，非官方保证，本项目仅将其转译为“第一拍给可理解的事情”，不硬编码秒数。

平台样本给出的更稳结论是：真实、可讨论的人和具体生活阶段，比通用的“制度观察＋物件清单”更接近观众参与；但任何外部样本都不足以证明新稿会爆。

## 已完成的 Arena 改造

- 新增 `skills/arena-screenplay/`：主 Skill、剧本契约、抖音原生剧本边界、拆文语料用法、审读契约；
- 新增 `arena_screenplay_check.py`：只做机械结构检查，区分 `mechanical_status` / `editorial_status` / `release_status`；
- 新增 `arena_screenplay_review.py`：生成带正文哈希的审读骨架，默认 `editorial_status: REQUIRED`，不伪造通过；
- `arena.runtime.json` 改为 `screenplay` 主项目，旧 fuben 管线显式标记 legacy；
- `AGENTS.md` 和运行文档改为 Arena 剧本路由；
- `find-skills` 已确认安装在 `.agents/skills/find-skills/`；适合的 `short-drama-write` 已在项目级安装，但不再让它替代 Arena 的项目契约；
- `skills/story-setup/scripts/deploy-antigravity-skills.py` 增加 `arena-screenplay` 部署项。

## 后续写新集时的最小动作

1. 提供本集题面/原文/拍摄约束；
2. 先读相关原文，不先写“检索与方向”长报告；
3. 用一句话锁定主角目标、阻力和本集退出状态；
4. 直接写 `剧集/EP001/剧本.md`，每场写行动和结果；
5. 先由审读者指出具体断点，再定点改稿；
6. 跑机械检查；看到 PASS 仍要保留编辑层未验证项。
