# GitHub 来源评估：哪些适合人生副本

> 评估口径只有一条：**它能不能让“口播剧”更好看、更可复用**。做不到的，哪怕工程再大也不借。
> 引用位置都是 2026-09 检查到的仓库内容；原文件已取回本地做了对照（`/tmp/src/**`，沙箱重启会丢，结论已固化到本文件与新工厂的 references 里）。

## 一、你点名的五个仓库

### 1. `yaojingang/yao-open-prompts`（2.8k★）——**最有用，已经拆开用**
- 里面确认有：`prompts/06-ai-content/spoken-viral-script.md`（口播爆款文案）、`viral-remix-deconstruction-rewriter.md`（爆款仿写拆解与重构）、`humanized-writing/humanized-writing-polish-v3.md`（润色反 AI 腔）、`hook-opening-copy.md`、`douyin-viral-planner.md`。
- **借**：口播 5 层结构（钩子 0-5s / 铺垫 5-20s / 主体 20-50s / 升华 50-55s / 引导 55-60s）、每 10 秒一个价值点、情绪波浪每 15-20 秒一个小高潮、时长×字数对照表、骨肉分离（只借骨架不借表达）。
- **没借**：“10 万条爆款研究”“口播之神”这类**没有证据的权威声明**，以及输出格式里的排版仪式感。
- **落在**：`剧本工厂/references/口播语法.md`、`钩子库.md`。

### 2. `1-SKILL/jiaoben`（极小体量）——**借结构，不借承诺**
- 内容：一个 SKILL.md + 一个 `latest-rules.json`（6 条 hook 公式 + 平台规则 + hook 窗口 + 语速）。hook 公式库是**静态文件**（版本 1.0 / 2026-03-26），所谓“每 2-3 天更新”并未发生；“完播率从 8% 到 30%”属自我宣传，无数据。
- **借**：每稿 3 个 hook 备选；抖音 Hook 0-3s / 痛点 3-10s / 方案 10-40s / 行动 40-60s 的段落表；口播 3-4 字/秒；每句 ≤15 字；用“你”不用“大家”；hook 窗口硬常量；**把 hook 公式做成版本化文件**这个想法（新工厂用 `钩子库.md` 的“战绩”回填代替假更新）。
- **没借**：效果对比表、生态推广块（`npx skills add 1-SKILL/ai-skill` 这类夹带）。
- **落在**：`references/钩子库.md`（硬常量表）、`口播语法.md`。

### 3. `liuyunlong2021-wq/jc-xiachen-duanshipin-jiaoben`（4★）——**骨架方法论最强，借得最多**
- 内容：扒片模式 + 高保真改编模式 + `references/爆款结构组件库.md`、`高保真改编规则.md`、`结构金标准样例.md` + `scripts/validate_shooting_script.py` + 正/反向测试基线。
- **借**：结构指纹（开场钩子功能、人物功能位、阻力与证据阶梯、四类阶段奖励：得到/失去/部分接纳/解释、追更债务、自然争议）；高保真改编的**锁定 9 项 + 换壳 + ±15% 时长**；“先提取指纹再写稿”“不编造未见事实”“自然手持可以保留但不以晃动冒充真实”。
- **改写**：它的场景是家庭伦理竖屏短剧（真人多镜头）；新工厂把“镜头提示”降级为每 beat 一行，保留可拍性但不引入拍摄工业流程。
- **落在**：`references/结构指纹协议.md`、`兑现与加价.md`、`高保真改编.md`、`骨架库.md`。

### 4. `longmao-001/kesheng_skill`（0★，但体量最大）——**只借两条，其余是另一个战场**
- 内容：37.7KB 的 SKILL + 14 个 agent 角色 + 16 项 `check_*.py` 门控 + FAILURE-LIBRARY（F-01…F-61）+ 双通道审计；本质是**AI 视频制作团队 SOP**（主产物是分镜 prompt 与素材包）。
- **借**：① **判型先行**——“口播稿＝文案驱动 / 剧本＝戏剧动作驱动”，误判通道等于全盘白做（它的硬规则 #42/#43 原话）；② **失败图书馆**的思路——把“踩过的坑”固化成条目（新工厂用 `钩子库.md` 的失败模式 + `验收表.md`）。
- **没借**：多 agent 编排、16 项门控、素材入库/索引那一整套——**那是给“出片”用的，不给“写戏”用**；对口播剧本是纯负担。
- **落在**：`references/判型卡.md`。

### 5. `LiChangZheng10086/doyin_ai_video`（Electron 工具链）——**只借一个想法**
- 内容是抖音下载 + Whisper 转录 + 洗稿 + 分镜 + 成片 + Claude Skill 蒸馏。技能目录（`.claude/skills/*`）在仓库里是**符号链接**，直接抓取会失败（要读 `.agents/skills/...` 真身）。
- **借**：“**合集蒸馏成 skill**”这个动作——把一批对标内容沉淀成可复用资产，而不是一批报告。新工厂把它实现成了 `scripts/distill.py`（44 篇指纹 + 开场原句库）。
- **没借**：下载/转录/数字人/成片链路。**“剧本水”不是下游问题**。

## 三、搜索方法与局限（诚实项）

- 用过的查询：`短视频 剧本`、`口播`、`爆款文案`、`短视频脚本`、`分镜 脚本`、`hook 公式`、`抖音 skill`、`短视频 skill claude` 等 10 组；覆盖 GitHub 仓库搜索 + 指定仓库文件树核查。
- 局限：星数只在两位数以下的仓库不少（`kesheng_skill` 0★、`jc-xiachen` 4★），**但内容质量与星数无关**；同时 2k★ 的项目也可能只是提示词合集。**判断标准始终是“这个机制能不能直接进施工”。**
- 没有引入任何第三方运行依赖：新工厂是纯本仓内容 + 标准库 Python 脚本。

## 四、一句话总结

**最适配人生副本的是三件事**：`jc-xiachen` 的结构指纹与加价阶梯、`yao-open-prompts` 的口播秒表与钩子类型、`kesheng` 的判型先行。
其余大工程（多 agent、门控、数字人、成片）看着高级，但它们解决的是“怎么做得更多”，而你现在的问题是“怎么写得更好看”——**方向相反**。
