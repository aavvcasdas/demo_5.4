# Arena 运行时说明 —— 本会话怎样读懂并运行本仓库的 Skill / Agent

对应机器可读配置：[arena.runtime.json](../arena.runtime.json)（路由与契约见 [AGENTS.md](../AGENTS.md)）。

## 这是什么

本仓库的 `skills/*/SKILL.md` 和 `skills/story-setup/references/templates/agents/*.md`
原本是写给 codex / Claude Code / opencode 这类外部执行器读的。当前环境没有这些执行器，
而 **Arena Agent Mode 主会话本身就是执行器**。`arena.runtime.json` 是绑定配置：
它告诉 Arena agent 打开本仓库时怎样把仓库里的角色定义跑起来——不是把 SKILL.md
当作参考文章读一遍然后随手写，而是按配置逐阶段实例化角色、落产物、过机检。

## 运行方式（以人生副本写作为例）

1. **识别意图** → [AGENTS.md](../AGENTS.md) 路由表 → [fuben-write](../skills/fuben-write/SKILL.md) 管线（原生抖音口播 skill；网文任务才走 story-* 线）。
2. **逐阶段执行**，每阶段开始时先读配置指定的角色职责与 fuben-write 四份参考（搜索与质感／口播结构与节奏／代入感手艺／审读与改稿），
   产物写入 `作品/NN_主题/_运行/`：

   | 阶段 | 角色 | 产物 |
   |---|---|---|
   | 00 简报 | 主控 | `00_简报.md` |
   | 01 深读+检索+方向 | 策划 + 并行多路搜索（≥8，单批并发，四类质感覆盖） | `01_深读_检索与方向.md` → **用户选定方向** |
   | 02 场次单 | 策划 | `02_场次单.md`（可拍场景 + 判词压缩 + 器物三现表） |
   | 03 成稿 | 主笔（反流水账八件武器） | `03_初稿.md` + `正文.md` |
   | 04 审读+返工 | 审读（追看断点/念稿测试/反流水账复检/**账目对账**）+ 主笔分层返工 | `04_审读与返工.md` |
   | 04b 读通专项 | `fuben-review`（5.3：含账目档位/开头体检/红线工具引用三新项） | `审核报告.md`（含 `body_path`/`body_text_sha256`＋机检候选闭环表） |
   | 05 机检（可选） | `scripts/fuben_run.py`（默认含 craft 门禁）＋`scripts/fuben_products.py`（产物完整性） | `05_机检.json` |

3. **调用证据**不是话术而是文件：每个阶段产物真实存在、内容对应其职责、
   阶段 01 必须含主题深读、一次并行多批的真实搜索记录（**逐路表**：检索词、来源、借用的质感、用到哪场）
   和**分类型剧情方向清单 + 用户选定结果（原话引用）**——用户裁决：不调用搜索即任务失败；未经选定方向不得动笔。
   机检JSON是命令的真实输出。缺阶段产物＝调用未发生，不得声称走了管线；产物命名与数量由
   `python3 scripts/fuben_products.py 作品/NN_主题` 核验（`OK`=完整管线，`PARTIAL`=定向返修，`STALE`=报告未重绑）。
4. **主题边界**：以用户题面为准。题面是人生，题材元素（如游戏）只能做质感与道具，
   不能抢走主线；审读阶段专门核这一条。
5. **版本绑定**：`审核报告.md` 必须写当前 `body_path` 和 `body_text_sha256`。正文改动后，旧报告只能算 `STALE/PROVISIONAL`，不能继续给新稿背书；`scripts/fuben_loop.py review` 会把未绑定或过期的报告显式报出来。

## 诚实边界

- 外部执行器（codex / Claude Code / opencode / gemini-cli）若日后在本环境安装并认证，
  可在 `arena.runtime.json` 里把 `executors.active` 切过去，产物协议不变。
- 独立外部审读目前不可用；04 审读由主会话以审读角色在独立步骤执行，产物里注明这一点，
  不冒充多 Agent 会审、不虚构会话 ID。
- 机检 PASS 只说明无机械阻断，不说明好看；创作判断以审读阶段与用户验收为准。

首次按本配置执行的产出：`作品/79_把游戏当命的宅男/`（含 `_运行/` 全部阶段产物）。

## 问责（2026-09-24b · 因 79/81 复查新增）

- **报告见用即成文**：`_运行/NN_名称.md` 的日期目录必有「00_*.md」是定向返修说明；走全管线为 `OK`，只补条目为 `PARTIAL`，报告哈希未重绑为 `STALE`（`scripts/fuben_products.py` 的机器口令）。
- **复跑不假毕**：任何一次修订后，必须把「机检前 findings ↔ 机检后 findings」写进 04/补记；新引入 BLOCK/REVIEW 不许带进下一阶。
- **红线机器化（不靠血肉记忆）**：无烟/禁词/开头铁律/对白限额/账目档位由 `scripts/fuben_craft.py` 并入 `fuben_run` 默认检查，profile=reference 的原文校准除外。
- **借一次真 8 路**：01 的检索表必须能回看——批号、检索词、来源、取用之质感、用到哪场——一句「来源：知乎/搜狐」不算检索记录。
