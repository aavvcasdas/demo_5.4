## 二、改完之后的一句话

**规则归提示词，脚本归技术。** 写作者与审读者按 references 逐条自检、给行号证据、自评分；脚本只回答三类可复现的事实问题：文件在不在、数算得对不对、报告哈希还绑不绑当前正文。

## 五、运行方式对照（**之前的脚本如何运作 → 现在如何运作**）

### 之前（v2.0，门禁驱动）

```text
写作 → 每写完一版跑一排脚本：
  fuben_run --profile full   → craft 门禁：BLOCK/REVIEW/NOTE（禁词、开头、对白、账目档位、体量）
  fuben_craft --ledger       → 账目全表，mismatch 必须逐条闭环
  fuben_claims               → 站点字段/认领关键词对表
  fuben_viral                → 结构自评，缺口退出码非零
  fuben_consistency / setting_years / scene_check / density / hype …
→ 「改到不报错」成为事实上的目标（86 全绿，仍然 1k 播放）
→ 规则散在脚本词表与 SKILL 之间，改一句话要同时改代码、policy 与文档
```

### 现在（v3.0，提示词驱动）

```text
00 简报 → 01 检索≥8路＋选题三闸（用户选定）→ 02 人生时间轴（可对标拆文库同型样本）
→ 03 分块直写成稿（每站过块级三问；无烟/禁词自己搜）
→ 04 投手预演七问＋平铺扫描＋念稿＋账目手算表＋十项自评/五维对标（写进 04，带行号）
→ 04b fuben-review 读通专项（报告绑定 body_path/sha256）
→ 05 自检八问落纸（05_自检.md）
→ 技术核对（可选、只读事实）：
     python3 scripts/fuben_run.py 作品/NN_主题/ --json
     python3 scripts/fuben_products.py 作品/NN_主题
```

**差别**：

1. **判罚权回到人**：脚本不再说「你不许用这个词」「你这段太短」，而是由提示词要求写作者自己扫、给行号、写明保留理由。
2. **少一次「改到全绿」的往返**：以前 BLOCK/REVIEW 会驱动一轮改稿；现在只有「确定算错/输入坏了」才会 BLOCK。
3. **规则只有一处**：规则写在 SKILL＋references；改规则改文档，不用同步代码、policy、测试三处。
4. **对标替代自嗨**：结构好不好不再问脚本，而是与 `拆文库/` 39 篇真稿的五维分对照。
5. **技术底线还在**：产物齐备、报告哈希绑定、发布证据、数据台账照旧，防止「没走管线」和「旧报告背书新稿」。

## 六、87 篇体检结论与一条改法（示范新尺子怎么用）

- 十项自检 **19/20**：只有「反打与释放」1 分——反打是自己算账（合格），但**对手当场输了什么**没写实。
- 具体改法（留给下一篇或下次返工，不追溯已发布稿）：谷底（淋浴限时）之后补半站——**店长当众用你的算法核了成本并改了规则**（例如公示「单次淋浴成本 3.1 元」或给会员补权益），让「赢」落到对手的账本上。这正是拆文库 15《卖肾买 iPhone4》、21《PG 电子游戏》拿 23–24 分的手法：**赢要赢在对手的账本上**。
- 其余 9 项（三秒钩、主线、观众关系、节奏、谷底、物证、语言、账目、结尾）都已达标，可作为 v3.0 的正面样本。

## 七、风险与下一步

1. **风险**：删掉门禁后，质量完全依赖执行者是否真按提示词自检。对冲办法是「证据留痕」——04 必须有行号与自评分，审读报告必须有十项对照表；空口「已检查」不算。
2. **建议入库节奏**：v3.0 之后第一批 3 篇按「一次只改一个变量」跑（用户既有调参纪律）；87 已是 v2.0 样本，不要把它的数据算进 v3.0 的对照。
3. **扩展位**：短剧/漫剧剧本走 `.agents/skills/short-drama-write`（其原则「估算是参考不是门禁」与 v3.0 同向）；若要共用检索与拆文库，可在 `arena.runtime.json` 增加一条 `pipeline` 而不改动 fuben 主线。
4. **历史文档**：`docs/技能重构诊断-2026-09-28.md`、`docs/短视频Agent借鉴.md`、`skills/_archive/` 保留作历史证据，不再作为现行规则来源。
