# 3 · 口播与节奏（v2.0；v3.0.2 补「正文零算式」）

> 用户裁决：**时长不限，只要剧情节奏好不水，1–2 分钟都可以**。本文件把「节奏」写成可执行的检查项，字数只是结果。**这些检查项由写作者按提示词自问自答，机器不判。**

## 一、三秒：第 1 行就是钩（v2.0 最大的改动）

**数据**：72% 的用户在 3 秒内决定划走；前 3 秒留存权重约 40%；**仪式感开场（问候/身份/标签句）比「直接给结果或问题」跳出率高约 37%**（腾讯云开发者社区、jzl 等多方实测口径）。

因此：

1. **第 1 行 = 钩**，四型选一：
   | 型 | 长相 | 例 |
   |---|---|---|
   | 结果前置 | 先把结局/数字甩出来 | 「全村人都在问，他这钱是怎么领的。」 |
   | 冲突 | 两个人/两股力当场顶住 | 「护士把单子推过来，说这栏不能填本人。」 |
   | 反常 | 违反常识的一句话 | 「他越穷，村里越多人羡慕他。」 |
   | 悬念 | 一个必须知道答案的问题 | 「这份工作不用考试、不裁员，只要一个条件。」 |
2. **签名句「今天你要体验的人生副本是……」后置到第 2–3 行**（保住系列识别，把前 3 秒让给钩）。
3. 「系统提示」类标签 **≤2 行**，且必须自带信息或笑点；只当仪式的删。
4. **前 160 字内不许出现**：定义、科普、口径、身世交代、「今天我们来聊」。
5. 三条钩子备选（A/B/C）**每一条的第 1 行都得是钩**；把签名句放第一行的钩子不得列为推荐。

## 二、中段：每 15–25 秒翻一次面

- **换算**：按创作语感 4.5–5 字/秒，**15–25 秒 ≈ 70–125 字 ≈ 15–30 行短句**。
- **什么叫翻面**：新信息／新坏消息／新动作／新对手／关系变化——五者任一。重复同一件事的两种说法**不算**。
- **钩点表**（写进 02 与 04）：每站的钩点标行号区段；**两钩之间 >300 字必须压或删**。
- **中段禁信息真空**：不允许连续两段只是「再举一例」或「再有一种难」。
- **断崖点**：连续 30 秒纯介绍/回忆/抒情 → 砍掉或前置半句钩。
- **段落长度**：单站 ≤400 字；单屏一口气读不完的段落拆开。

## 三、结尾：金句 ＋ 互动钩

- **金句**：全篇判词 ≤2 句，最后一句落在 60–70% 之后的释放段，越长越亏（8–16 字最好记）。
- **互动钩**：给观众一个**具体动作**，不是「你怎么看」——
  - 提问型：「要是你，这栏你填谁？」
  - 征集型：「你身边有没有这样的人，说给我听。」
  - 立场型：「你觉得他算赢了吗？」
- **情绪现场语料优先**：互动钩的句式尽量从检索到的评论区原话里长出来（观众用过的说法，观众才会接）。

## 四、时长与字数（节奏优先）

| 节奏档 | 参考字数 | 参考时长 | 适用 |
|---|---|---|---|
| 短 | 900–1300 | 3–5 分钟（语感口径） | 单反转、单事件、切条 |
| **短平快** | **400–900** | **1–3 分钟** | 用户明确接受；冲完播、冲互动 |
| 中 | 1800–2600 | 6–9 分钟 | 一生跨度、多站推进 |

- **不设硬带**：写多长由钩点密度决定。用户 2026-09-28 授权「时长不限，只要剧情节奏好不水，1–2 分钟都可以」，写进 00 简报即可，不用再逐篇确认。
- **两套估时不要互相冒充**：创作语感 4.5–5 字/秒（含呼吸）／机检 6.4 字/秒（不含停顿）。
- **短不等于快**：1–2 分钟的稿子同样要有压制—谷底—反打（压缩到各 2–4 行），不能因为短就只写一个段子。

## 四·补 · 数字纪律：口播不是账本（v3.0.2，用户 2026-09-30「不要有太多的数字在运算」）

观众听口播是按秒走的，听见「先减后除再乘」的那两秒就是在听账，不是在看你。

- **正文零算式**：加、减、乘、除、百分比换算、单位换算一律不进口播稿，写进 `04_审读与返工.md` 的账目手算表。
- 正文数字只准四类用途：**对比**（一进一出）、**事实**（总数，如年卡两千八）、**背叛**（数字打脸，如涨一点二公斤）、**动作**（走四十分钟）。
- 数字总量像撒盐：一整篇短平快稿件，能删到十个以内就别留十五个（88 v2：全篇约 10 个数字 token，v1 是 68 个）。
- **谷底不放数字**：谷底那一下要由人的反应完成（半句话没说完、沉默、放下筷子）。
- 账目仍然要能反算——只是反算发生在后台表里，不发生在观众耳朵里。

## 五、口播体裁纪律（保留）

1. **旁白驱动**：引语字数占比 ≤10%，每站 ≤1 句原话钉子，全篇钉子句 ≤8；**禁「你说他说」乒乓回合**，交锋用旁白转述。
2. **口语短句成行**：5–12 字是语感指纹（不是机检规则）；情绪最痛处用最短句。
3. **抽象只准落在身体、器物、数字上**，禁情绪形容词宣布（「心酸」「孤独」「感慨」一律不许出现）。
4. **禁书面腔/AI 腔**：首先、其次、然而、随着、不禁、值得一提、眼眶一热、五味杂陈……（**写完后逐条搜一遍自己改**；完整清单见 [5_代入感与禁忌.md](5_代入感与禁忌.md)。脚本不再扫这一项，靠提示词与自觉。）
5. **每段能当分镜拍**：拍不出来的段落压成一句判词。

## 六、分块写与接缝（v3.0.4 · 用户问「为什么要分块写、块与块能平滑过渡吗」）

### 6.1 为什么分块：它是写作过程，不是交付格式

- **分块＝写的时候一次只写一站（≤35 行），写完立刻回读、过块级三问**。目的只有一个：**防漂移**——一口气写整篇，模型会越写越短、反复总结、把前面埋的物证忘掉。
- **交付物永远是连成一片的整篇**。观众不该听出任何「块」。所以「分块」必须配一条补偿动作：**整篇连读**（不是只在块内回读）。

### 6.2 块与块为什么会不顺（三个真实成因）

1. **各站分别起笔** → 每一站都像重新开场（又介绍一次身份、又交代一次时间）；
2. **同一句式连着用** → 「那天…」「后来…」连着起头，听感变成分段的清单；
3. **缺因果** → 上一站只是「发生了什么」，下一站只是「又发生了什么」，中间那口气没接上。

### 6.3 行业怎么做（GitHub / 公开项目的实际写法）

| 来源 | 做法 | 对我们的用处 |
|---|---|---|
| `huangbai-AI/one-prompt-video-skills`（huangbai-script） | 脚本用表格式 **`阶段｜口播｜备注（画面/分镜）`**，一句 ≤20 字、**一句对应一个画面动作**；接缝靠三类固定件：**交付感句式**（「我已经把以上内容整理成…」）、**递进抛点**（「当你以为…已经很不错了，那接下来的才是硬菜」）、**对比句式**（不是…而是…，一头一尾各一次形成呼应） | 证明「分阶段写」是行业常规，但每段之间必须**显式设计一个接件**；也印证我们的「每段能当分镜拍」 |
| `nanyin-gif/koubo-copywriter-lite`（爆款口播结构库） | 正文框架六选一；其中 **「场景连拍：两三个短场景并列（不用连接词）」**；节奏「每 10–15 秒一个信息点/情绪点」；单句尽量 ≤20–25 字 | 顺不顺**不靠连接词**，靠共同的主语与时空连续；连接词堆多了反而假 |
| 讯飞 `short-video-script`（skill 平台上的分镜脚本工具） | 分镜表里**明确带「转场」列**；方法论写「**每 3 个信息点后做一次小总结或过渡**」 | 过渡是**显式设计项**，要在结构表里写出来，不能靠感觉 |
| `xixihhhh/clipforge`、`Seedance2-Storyboard-Generator` | 成片阶段把转场当参数显式指定（画面渐暗、天色变化、延长衔接） | 同一条原则：接缝要写出来，才有人（或模型）替它负责 |

### 6.4 我们的规则（写稿时照做）

1. **接缝三要件**（写进 SKILL 阶段 3，04 逐处复查）：
   - 每一站的**第一行**必须接住上一站**最后一行**的同一件事（同一个动作／物件／时间／一句话／情绪）；
   - **禁连续两站同式起笔**；
   - **场景连拍可不加连接词**，但必须共享主语或时空。
2. **接缝扫描（04 必做）**：列一张表 `接缝位置（站 N→N+1）｜上一站尾行｜这一站首行｜接法（因果/转折/时间/物件）｜顺不顺`；不顺的当场修。
3. **整篇连读（写完后）**：出声从第 1 行读到末行，专听接缝处；读着跳、重复、像重新开场＝返工那一处。
4. **05 留结论**：`接缝 N 处，全部顺` 或 `接缝 X 处，第 N 处已修（改了什么）`。

> 一句话：**分块是为了写稳，接缝是为了听顺；写完必须整体连读一遍，把块缝抹平。**
