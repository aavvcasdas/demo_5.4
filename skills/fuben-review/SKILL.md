# 人生副本审核

**审的是观众有没有继续听的欲望、期待是否得到兑现，不是检查表是否全绿。** 本账号默认重视强开头、爽感、伏笔钩子和侧面描写；以本次用户要求为准，不拿“日常可以平淡”驳回明确的创作目标。能独立审则独立审，否则标 solo 自检；不冒充多 Agent 会审。口播稿的创作标准见 [2_选题与结构](../fuben-write/references/2_选题与结构.md)、[3_口播与节奏](../fuben-write/references/3_口播与节奏.md)（首行即钩、签名后置、爽点四段、互动钩）、[5_代入感与禁忌](../fuben-write/references/5_代入感与禁忌.md) 与 [7_自检与评分.md](../fuben-write/references/7_自检与评分.md)（十二项过线清单＋五个自查问题：不打分、不跟拆文库比分数；v3.4 起第 12 项＝场间过渡；v3.5 起前置门禁＝选题四关＋剧本五关＋情绪关）：流水账四特征、场景可拍测试、物证三现/数字判词链/拆穿旁白是否落地、断崖点，与追看问题同为创作审查项。

> **v6.0（2026-09-30）**：创作类门禁脚本（craft/claims/viral/consistency 等）已按用户裁决删除，规则回到提示词。审读**不再引用机检规则号**，改为直接引原句＋行号给出判断；技术核对（输入/算术/产物/哈希绑定）仍可作底线证据（`fuben_run`、`fuben_products`），但**PASS 不构成创作通过**。

## 1. 先读当前正文，判断追看是否成立

确认范围是全文、短版、切条还是成片，读对应的实际版本。已有设定和来源按需查；旧报告、作者自评、场面表不能代替正文。没有正文就不做全文判断；没有音视频仍可审文本，但不声称听感或画面已验证。

优先检查以下问题，直接引用原句说明，不要求作者补表：

- **开头为什么值得继续听？** 观众产生了什么具体疑问、期待或情绪？若只复述题目、介绍身份、描述普通动作，没有牵引，就指出应从哪场冲突、哪个反常后果或哪个动作切入。不能用抽象的“开头不错”放行。
- **中间在推进，还是在换段闲聊？** 关键行动是否改变处境；前一个小兑现是否带出下一层期待？指出最早可能划走的具体段落及原因。刺激开头接流水账仍是失败。
- **爽点有没有真正演出来？** 蓄势在哪里，兑现是哪句/哪场，兑现后谁的处境、选择或话语权变了？若关键时刻只剩“众人震惊”“你终于赢了”，要求展开交锋和反应，不靠旁白宣布爽。
- **伏笔和侧面描写是否有效？** 前面的细节能否支持后面的揭示；有没有临时空降的答案？对手、旁人或环境的变化是否帮助观众判断并推动后续，而不是装饰性的表情堆砌？

不强制每篇同一种反杀，也不发明固定节点数、情绪分、百分比或动作密度。判断的是具体效果，不是术语命中。若本次用户已指出开头弱或没爽感，先解决这些问题，不转去处理与之无关的工程待办。

## 2. 给诊断，也给能用的改写

主控按 [副本 Agent 方法·审读与返工](../story-short-write/references/genre-styles/人生副本_Agent方法.md#3-审读先指出失去追看欲的位置再决定退到哪一步) 路由：切口/主线不成立回策划，关键戏没展开回主笔，只有表达问题才局部润色。独立审读只收当前正文、brief和必要事实，不以作者自评或旧通过报告作依据；独立审读者给诊断，主控再委派改稿，不让“我改了”代替复审。用户只要审核时不自动改稿；只研究Agent时不启动创作。

保留有效的声音和段落。开头弱，给改后的开头并接到第一段实质发展；爽点落空，展开那一场；主线散，重排事件，不只改几个形容词。不能只换一句钩子，后面照抄旧流水账。

用户要口头意见就直接回复；要改稿就交改稿。说明改动为何服务于追看与兑现，但不要让解释比正文更长。只在用户需要时落审核报告，记录当前版本、solo/独立方式、关键原句、改法和仍未验证的项。没有真实偏好或平台反馈，不许报“必爆”“恢复原作水平”或虚构胜率。

## 3. 读通专项：从当前正文取证

在创作效果之后，单独通读**当前完整稿**。不要只读被点名的句子，也不要拿写前设定、台账或旧报告代替正文。至少检查：

1. 标题承诺与主要事件是否吻合；判断事件承担的功能，不用热词、词频或名词次数判跑题。
2. 物件、食物和人物是否有未解释的身份、位置或状态漂移；先判断是否同一实例、是否发生了合理转移。
3. 时间表达是否指向同一事件，起止点能否接上；不同事件的“两周／一个月”和夜间状态不自动矛盾。
4. 多人场景中的代词是否有清楚先行对象；目标是可辨认，不强迫所有配角取名。
5. 问答是否有观众可理解的回应关系；玩笑、借代和故意答非所问可以保留，但须有语境支撑。
6. “第一／第二／第三”等序列是否维持同一分类，或在改变压力来源时给出明确转向。
7. “连、却、因此、再然后”等连接词所承诺的递进、转折或因果是否成立。
8. 明确计数主张是否准确，并分别确定外层句子与内层短语的计数边界。
9. 专业术语、俗语、角色自我安慰、作者旁白事实和玩笑是否混淆；未核实说法不能当专业事实。
10. 关键转折是否由人物需要、情绪、关系或认识支撑，结尾是否以行动兑现而非只输出金句。
11. 修改后是否遗留旧场景、旧食物名、旧时间、旧称呼、旧字数主张或旧审核结论。
12. **账要平（人工手算）**：金额、位数、档位（A/B/C 级）、单价×数量、总−支出=余，逐项按文内口径在报告里列表反算；同一器物/欠款的数两处必须一致，要留差异必须有人物点破。对不上且未处置的，不得 APPROVE（81 案：4700↔「四千」、两千多称「A5」）。
13. **开头 3 秒体检**：按 [3_口播与节奏·一](../fuben-write/references/3_口播与节奏.md)——**第 1 行必须是钩**（结果/冲突/反常/悬念）、签名句在第 2–3 行、160 字内禁定义前置、系统提示 ≤2 行且自带信息；`钩子备选.md` 三条同检（签名句开头或讲解腔钩子不得推荐）。
14. **正文零算式（v3.0.2）**：正文里若出现加、减、乘、除、百分比或单位换算（「净多两百」「一万八除七千七」这类），逐个抄进行号并判：删掉它观众还能不能看懂？能看懂＝运算只该待在 `04` 的账目表里，要求移出；除非该算式本身就是人物的动作或笑点。同时点出**谷底是不是靠数字打脸**——是的话要求改成人的反应。
15. **见证链（v3.0.2）**：数出正文里除主角外**具体的人**（有称呼或固定动作）及其行号；释放那一下有没有人在场看见并接住（引台词/动作）？没有见证人的释放判「独自完成」，报告里写明并要求回阶段 2 补人（88 v1 → v2 的修法）。
16. **接缝检查（v3.0.4）**：逐处看站与站的交界——这一站第一行有没有接住上一站最后一行？有没有连续两站同式起笔？读起来像不像重新开场？（分块写法的通病）。另检查正文里有没有靠「连接词堆砌」假顺（「于是」「所以说」连着来）——顺不顺靠同一件事在推进，不靠虚词。
17. **笑点/名场面（v3.0.5）**：逐站检查是否至少一处笑点或名场面（引原句/动作）；谷底那一站**不该有**笑点；笑点是否从热帖热评借机制而非整句抄；有没有嘲笑身材、弱者、打工人。题面或方向含共鸣/搞笑时，这一项按 11 项表给分。
18. **戏关（v3.3）**：逐站数「两人同框、有来有回」的戏（≥2 个来回＋台词）：每站都有吗？全篇 ≥6 场吗？配角是不是各自一个腔（引至少两处对白对照）？整篇是不是从头到尾只有主角一个人在总结？
19. **悬念与底牌（v3.3）**：找出全篇最大的反转/谜底，报出它出现的行号与百分比；**≥55% 才算过关**；开场第一句是否已经用掉了唯一的底牌？
20. **代价关（v3.3）**：反打/曝光/反击之后，主角多付了什么（被反怼、被拉黑、被嘲笑、钱回不来、欠新债）？零成本获胜＝不合格，要求补。
21. **主角毛边与结尾（v3.3）**：主角有没有 ≥2 处缺点/自欺/嘴硬/双标（引原句）？结尾是不是一句**人能说出口**的话＋一个可拍动作？有没有**作者总结腔**（替观众下结论的聪明话）？判词超过 1 句、或不是人话，要求改。
22. **对白密度与转述（v3.5 → v3.6 → v3.7 → v3.8）**：报引语占比数字（上限 15%、目标 3–5%）与钉子处数（全篇 ≤3、每场 ≤1）；有没有连续 3 行以上引号交替？**转述有没有把戏说丢**——抽一处对白报「改前→改后」，来回层数与信息是否都还在。**v3.7 加报三样（用户 2026-10-02 二次反馈「还是太多对话了……好多『你说他说』」）**：①**说话人标记行**（他说／你说／他问／你答）÷ 总行数（须 ≤ 每 10 行 2 行；任取连续 10 行 >3 行＝返工）；②**最长连续说话人交替**（≤2 行，每站 ≤1 处、全篇 ≤5 处）；③**每站无口白段**（≥3 行，靠动作／器物／数字推进）。三法（结果化／器物化／静默化）见 [3_口播与节奏](../fuben-write/references/3_口播与节奏.md) 8.5。**v3.8 名额制（用户同日二次退回「还是太多对话了」）**：报四个数——**说话人标记处数（≤6，且每站 ≤1、任意两处不相邻）／引号台词处数（≤3）／每站连续无人开口最短行数（≥5）／台词事件总数（含屏幕字与无标记引述）**；优先**字替话四法**（屏幕／器物／结果／记录，见同文件 8.6）。**交锋不能少**：每站仍须有两人同框、有输赢，只是用动作、器物、数字、结果演。
23. **情绪关（v3.5 门禁，v3.6 配方）**：深度／笑点（≥3 处不自觉会笑）／共鸣／爽——**四项至少两项成立**，逐项引原句与行号并**归型**（深度＝行话透视/自知独白/被问住；笑点＝同化/称呼通胀/错位的正经；共鸣＝家当细节；爽＝小反抗）；有没有把「可怜」当「好笑」、把「作者总结腔」当「深度」？
24. **接缝写法（v3.4）**：列全篇接缝（缝 N→N+1｜上一场末行｜下一场首行｜写法）；**写法 ≥6 种、无同一种连用、无连接词开场**（于是/后来/从那以后/就这样）；抽 3 处遮住下一场首行朗读——听得出「要出事」吗？接缝处有没有重新介绍身份/时间？
25. **台词回声（v3.4）**：有没有复现的台词？两处是否**一字不差**、第二次含义是否变了、旁边有没有数字或人？有没有用旁白去解释「是一样的」（有＝不合格）？
26. **结尾纪律（v3.4）**：最后 15 行里同一个主题说了几次（须 1 次）？开场抛出的矛盾/物件在哪一行回扣？
27. **题材边界（v3.4）**：网贷/赌博/打赏/诈骗/医疗等：有没有平台名、机构名、利率、操作步骤？有没有把伤害写成猎奇？镜头是不是对着人和后果？
28. **红线复扫（自己搜）**：在正文、短版、钩子三个文件里各搜一遍「烟」与禁词表（[5_代入感与禁忌·四/五](../fuben-write/references/5_代入感与禁忌.md)），报告命中行号与处置；禁止「烟字 0」这类无出处手报——把你搜的关键词写进报告。

跨句问题必须同时给两端证据。对每个发现写：

```md
- 规则或问题类型：
- 文件与原文位置：
- 原句及相关对照句：
- 为什么影响理解：
- 确定错误 / 待确认 / 可接受表达：
- 最小修复建议：
- 复核结果：
```

“确定错误”只用于当前文本已有充分证据的问题；需要确认对象、时间起点、玩笑意图或历史版本时标“待确认”。不为凑数量升级严重度。

## 4. 返工允许局部改，但必须查关联依赖

场景、关键食物／道具／人物称呼、时间点或跨度、标题核心概念、主要压力源、结尾金句或字数主张发生变化时：标明改动对象，查找全文直接引用和间接指代，修复受影响段落，再检查场景接缝、题意回扣与当前完整稿。改稿后必须重新审读并生成对应新版本的结论，不能复用旧稿的“通过”。全文重写不是默认答案，也不能免除复核。

审核报告必须记录当前正文路径 `body_path` 和 `body_text_sha256`（以 UTF-8 解码并统一换行为 `\n` 后的 SHA-256；可直接采用 `python3 scripts/fuben_run.py 作品/NN_主题 --json` 输出的 `body_path` 与 `inputs.body_text_sha256`）。这是**技术绑定**，防止旧结论给新稿背书。报告哈希与当前正文不一致时，报告状态只能是 `STALE/PROVISIONAL`，不得为新稿背书。APPROVE/FIX 报告还须含「**自检对照表**」：按 [7_自检与评分.md](../fuben-write/references/7_自检与评分.md) **十二项清单**给分与证据行号（v3.4 起满分 24、判定线 20；旧报告保留当时口径），并写**情绪关四项兑现行号**与**引语占比数字**（v3.6），并列出账目手算表、无烟/禁词搜索结果；返工后把「前次低分项 → 本次分数」一并写上。最低限度写成：

```md
body_path: `作品/NN_主题/正文.md`
body_text_sha256: `<64位哈希>`
review_status: PROVISIONAL / BLOCK / FIX / APPROVE
十二项自检：<分数/24>，最低三项＝…，证据行号见正文；情绪关：深度/笑点/共鸣/爽 成立两项＝…（行号）；引语占比 X%（钉子 N 处）；无烟搜索：三个文件「烟」0 命中；账目手算：N 条主张全对（表见正文）；笑点覆盖：N/N 站、谷底 0 个
```

缺 `body_path` 或缺 `body_text_sha256` 的报告，都不能拿来证明当前正文已经审过。

## 5. 事实与技术核对作底线（不是创作结论）

核对本篇真正涉及的事实、指代、因果、账号约定和来源；分清角色误信、倒叙、虚构和现实断言。精确数字确实错误要修，但不能把修几个字当作完成创作审核。

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --json            # 输入/算术/指标（BLOCK=确定的输入或算术错误）
python3 scripts/fuben_run.py 作品/NN_主题/正文.md --style     # 可选：AI 腔句式候选，advisory
python3 scripts/fuben_products.py 作品/NN_主题                # 阶段产物与哈希绑定是否齐全
```

- 脚本只出两类东西：**确定的输入/算术错误**（必须清零）与**描述性数字**（字数/行数/估时/AI 腔候选）。
- 结构、节奏、禁词、对白、体量、账目档位**不再有机检门禁**——它们的判断依据是本文件第 1–4 节、`7_自检与评分.md` 与 `/references/` 里的提示词规则。
- **PASS 只说明没有已检出的机械错误，不评开头、爽感或可发布。**

**创作结论与机器状态分开：**
- `FIX`：开头留不住、主线散、蓄势无兑现、伏笔生硬或侧面无效，即使机检全绿也不能放行。给位置和实改。
- `APPROVE`：当前范围内，创作目标有具体正文证据且无已知阻断。不是“没查出错”就批准，也不是流量预测；solo 不升级成独立认定。
- `BLOCK`：明确不能按要求交付的问题尚未解决。
- `PROVISIONAL`：完成当前可做的判断，但关键素材或证据不足；说明缺什么，不假装全文或成片已经通过。

## 6. 仅在制作／发布任务中审媒体

用户要求后才读取 [成片逐镜清单](references/成片逐镜清单.md)，审真实声音、字幕、镜头及素材权限。字数/语速、ffprobe 元数据都不是听完视频。`fuben_release.py`只做证据验收；改稿使旧版本证据失效，工具通过不等于账号主授权或平台通过，不代发。
