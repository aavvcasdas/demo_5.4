# 人生副本剧本审读（v6.0）

**审两件事：观众有没有理由继续看／这一场拍不拍得出来。** 不审「产物齐不齐、哈希对不对、清单填没填」。
能独立审则独立审，条件不允许就自检并如实标注；**不冒充多 Agent 会审，不虚构会话 ID**。

**v6.0 删掉的东西（2026-09-29 用户裁决「删到会咬人就行」）**：`body_text_sha256` 报告绑定、`STALE_REVIEW_REPORT` 状态机、机检候选逐条销账表、`fuben_products.py` 产物门禁、`fuben_viral.py`/`fuben_claims.py` 那类数关键词的存在性自评、14 条读通专项清单。理由：哈希绑定只证明「文件没被改过」，不证明有人读过；数「物证出现 11 次」能被格式刷出全绿。**借来的新纪律**（zenstory `short-drama-review`）：引用只用文件名、场号、行号或短引文，不建哈希、不建 record ID、不建第二套状态。

## 1. 先读当前稿，按四扫找划走点

读 `剧本.md`（有 `旁白.md` 时对照读配音轨）。旧报告、作者自评、分场表不能代替正文；没有正文不下全文结论。逐场扫四样（判据来自口播稿的实战检验，不是抽象标准）：

1. **衔接断裂**：上一场的最后一句与这一场的第一句之间，观众能不能自然接上？缺的那一句是什么？（典型：从个案跳到大道理、前一个话题没收）
2. **密度掉了**：这场有没有在重复已经演过/说过的信息？删掉它下一场还成立吗？成立＝装饰。
3. **念不出来**：单句 >30 字、书面腔（「然而/随着/不禁」）、自问自答连打、术语没解释。
4. **数词与比喻**（v6.1 新增，作品 88 初稿就是这么退步的）：可念轨是不是在念发票（数字串 >70/千字、量词数串 >20/千字）？同一个数是不是第 4 次出现？「三年/五年」是不是被当装饰词反复挂？比喻是不是中途换了（一篇只养一个）？修法固定：**把数挪进画面里的单据特写，旁白只留一句人话结论**——不是把数字改小。

**再核可拍性**（本项目特有，别处不查）：
- 每场有没有 `画面：` 行，画面行是不是「这一场能拍到的东西」；
- 旁白有没有在宣布画面已经演的东西（有→删旁白，不是补画面）；
- 对白是否 ≤25%（字数口径）且只做激将/预警/刻度；连续三行「你说／他说」＝乒乓，改旁白转述；
- 局面变化是不是主角自己动手的，对手当场输了什么有没有写清。

`fuben_craft.py <剧本.md>` 的数字预算读数（`NUMBER_STUFFING`/`NUMBER_REPEAT`/`DECOY_SPAN`）只是提示，密度低不代表稿子好——最终仍按上面四扫人工判。每条发现给**位置＋原句**，并标 🔴 必改／🟡 建议／🟢 保留（一句理由）。**🔴 不清零不得给「可以发」**。不强制每篇同一种反杀，不发明固定节点数、情绪分、百分比配额；判断具体效果，不做术语命中。

## 2. 给诊断，也给能用的改写

- 切口/主线不成立 → 退阶段 1（选题三闸重过）；场排坏了（并列、缺对手、谷底没有动作）→ 退阶段 2；只有表达问题 → 就地改。
- **开头弱**：直接给改后的第一场（首行钩＋签名后置＋画面锚），不要只说「建议加强钩子」。
- **爽点落空**：展开那一场（谁做了什么、对手怎么接的），不许用「众人震惊」或旁白宣布。
- 保留作者有效的句子与段落；用户原文优先，不抹平个性。**只研究不改稿时不动文件；用户只要口头意见就直接回复，不为「完整」创建报告。**
- 说明改动为什么服务追看与兑现，但**解释不许长于正文**：一份审读意见 ≤60 行，改稿说明每条两三行足矣。

## 3. 落盘时的最小格式（用户要报告才写）

```md
# 审读意见 · 作品/NN_题名
版本：剧本.md（末场「场6 · 年底榜单」）／审的是这份文件，改稿后本意见作废
结论：可发 / 改后可发 / 退回阶段2 / 退回阶段1

🔴 场4 — 旁白「你这一年其实也没练」在宣布画面（场4 画面行已写你站在器械前没动）
  → 删旁白这一行，把「没练」交给教练那句问话
🟡 场2 → 场3 之间缺一句「为什么非买这张卡」→ 在场 2 末补一个被拒的动作
🟢 场5 两行数字保留：是账目可反算的唯一入口（10 字）
```

不写 `body_text_sha256`、不写机检候选闭环表、不写 PROVISIONAL 状态机。**改稿后重跑一遍机检并把「改前→改后」的 findings 差异写在意见末尾即可**（这是防「改了没复查」，不需要哈希）。

## 4. 底线用工具，红线用工具

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --profile full --json          # 优先读 旁白.md；红线/禁词/开头/对白/账目/体量/可拍性
python3 scripts/fuben_craft.py 作品/NN_主题/旁白.md --ledger                # 数字判词链对账
python3 scripts/fuben_run.py 作品/NN_主题/钩子备选.md --profile short --json  # 钩子文件同扫（体量项对文档无意义，忽略即可）
```

- `NO_SMOKE`（烟）是 BLOCK，无豁免；`LEDGER_*` mismatch、`VOLUME_UNDER_FLOOR`、`SCENE_NO_VISUAL` 未处置不下「可发」。
- 对白与引语占比一律引用工具输出的规则号与数字，**禁止「我看了一遍觉得还好」式的手工自报**；工具没跑成就如实说没跑成。
- 事实边界：角色误信、倒叙、虚构与现实断言要分清；精确数字错了要修，但不能把修几个字当成完成审读。

## 5. 结论口径

- **改后可发**：当前范围内，创作目标有正文证据、🔴 已清、红线工具已核。这不是「没查出错」，也不是流量预测。
- **退回阶段 X**：主线或分场坏了，说明退回哪一步、那一步要产出什么。
- 机检 PASS 只说明没有机械阻断；`审读意见.md` 只说明有人读过并点名了位置。两者都不代表能爆。
- 制作/发布阶段（用户点名才做）：真实声音、字幕、镜头与素材权限另审；字数与语速不是听完视频，元数据不是画面已核。
