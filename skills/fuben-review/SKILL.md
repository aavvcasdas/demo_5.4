# 人生副本审核

**审的是观众有没有继续听的欲望、期待是否得到兑现，不是检查表是否全绿。** 本账号默认重视强开头、爽感、伏笔钩子和侧面描写；以本次用户要求为准，不拿"日常可以平淡"驳回明确的创作目标。能独立审则独立审，否则标 solo 自检；不冒充多 Agent 会审。

> **v7.0（2026-10-11）**：与 fuben-write v4.0 同步松绑（诊断见 `docs/skill限发挥诊断与松绑-2026-10-11.md`）。原 29 条合并为 **12 问**；**废除全部报数配额**（说话人标记处数/引号处数/无人开口行数/写法种数）——这些指标模型最好刷，刷达标了稿子照旧闷。保留：引原句＋行号的证据纪律、红线扫描、账目手算、哈希绑定。手艺细节仍见 fuben-write 的 references，本文件只留判断视角。

## 1. 先读当前正文，判断追看是否成立

确认范围是全文、短版、切条还是成片，读对应的实际版本。旧报告、作者自评、场面表不能代替正文。没有正文就不做全文判断；没有音视频仍可审文本，但不声称听感或画面已验证。

**十二问（每条引原句＋行号；答不出就是返工点）**：

1. **开头为什么值得继续听？** 观众产生了什么具体疑问、期待或情绪？若只复述题目、介绍身份、描述普通动作，没有牵引，就指出应从哪场冲突、哪个反常后果或哪个动作切入。不能用抽象的"开头不错"放行。
2. **中间在推进，还是在换段闲聊？** 关键行动是否改变处境；前一个小兑现是否带出下一层期待？指出最早可能划走的具体段落及原因。刺激开头接流水账仍是失败。
3. **爽点有没有真正演出来？** 蓄势在哪里，兑现是哪句/哪场，兑现后谁的处境、选择或话语权变了？若关键时刻只剩"众人震惊""你终于赢了"，要求展开交锋和反应，不靠旁白宣布爽。
4. **伏笔和侧面描写是否有效？** 前面的细节能否支持后面的揭示；有没有临时空降的答案？对手、旁人或环境的变化是否帮助观众判断并推动后续？
5. **戏够不够？** 有没有连续两大段只有主角一个人自说自话？每站有没有一场人与人同框的交锋（用台词演还是用动作/器物/数字演，都算——**不再数场数、不再数说话人标记**）？禁的是连续 ≥4 行不推进的乒乓和全员同腔。
6. **悬念与底牌**：全篇最大的反转/谜底出现在哪一行、占全篇几成？开场第一句是否把唯一的悬念用光了？
7. **代价**：反打之后主角多付了什么（被反怼/被拉黑/钱回不来，或正向投入：多跑三公里/多花一小时）？零成本获胜＝不合格。
8. **主角毛边与结尾**：主角有没有缺点/自欺/嘴硬/小算计（引原句）？结尾是不是一句**人能说出口**的话＋一个可拍动作？有没有**作者总结腔**（替观众下结论的聪明话）？
9. **读通专项**（通读当前完整稿，不只读被点名的句子）：标题承诺与主要事件是否吻合；物件/食物/人物有没有未解释的身份或状态漂移；时间表达能否接上；代词有没有清楚先行对象；序列是否维持同一分类；连接词承诺的递进/转折是否成立；修改后有没有遗留旧场景旧称呼旧结论。
10. **账要平（人工手算）**：金额、位数、档位、单价×数量、总−支出=余逐项反算；同一数字两处不一致必须有人物点破。对不上且未处置的，不得 APPROVE（81 案：4700↔「四千」）。
11. **红线复扫（自己搜）**：在正文、短版、钩子三个文件里各搜一遍「烟」与禁词表，报告命中行号与处置；把搜过的关键词写进报告，禁止「烟字 0」这类无出处手报。混合源有没有虚构声明；高危题材有没有平台名/利率/操作步骤。
12. **口播三关**：①**开头 3 秒**——第 1 行是钩、签名句第 2–3 行、160 字内禁定义前置（`钩子备选.md` 三条同检）；②**正文零算式**——出现运算的逐个抄行号判"删掉观众还懂不懂"，同时看谷底是不是靠数字打脸；③**朗读关**——大声读完，哪几行嘴不顺。

跨句问题必须同时给两端证据。对每个发现写：

```md
- 规则或问题类型：
- 文件与原文位置：
- 原句及相关对照句：
- 为什么影响理解：
- 确定错误 / 待确认 / 可接受表达：
- 最小修复建议：
- 复核结果：
```

"确定错误"只用于当前文本已有充分证据的问题；需要确认对象、时间起点或历史版本时标"待确认"。不为凑数量升级严重度。

## 2. 给诊断，也给能用的改写

主控按 [副本 Agent 方法·审读与返工](../story-short-write/references/genre-styles/人生副本_Agent方法.md#3-审读先指出失去追看欲的位置再决定退到哪一步) 路由：切口/主线不成立回策划，关键戏没展开回主笔，只有表达问题才局部润色。独立审读只收当前正文、brief 和必要事实，不以作者自评或旧通过报告作依据；独立审读者给诊断，主控再委派改稿，不让"我改了"代替复审。用户只要审核时不自动改稿；只研究 Agent 时不启动创作。

保留有效的声音和段落。开头弱，给改后的开头并接到第一段实质发展；爽点落空，展开那一场；主线散，重排事件，不只改几个形容词。不能只换一句钩子，后面照抄旧流水账。

用户要口头意见就直接回复；要改稿就交改稿。说明改动为何服务于追看与兑现，但不要让解释比正文更长。只在用户需要时落审核报告，记录当前版本、solo/独立方式、关键原句、改法和仍未验证的项。没有真实偏好或平台反馈，不许报"必爆""恢复原作水平"或虚构胜率。

## 3. 返工允许局部改，但必须查关联依赖

场景、关键道具、时间点或跨度、标题核心概念、主要压力源、结尾金句发生变化时：标明改动对象，查找全文直接引用和间接指代，修复受影响段落，再检查场景接缝、题意回扣与当前完整稿。改稿后必须重新审读并生成新版本结论，不能复用旧稿的"通过"。全文重写不是默认答案，也不能免除复核。

审核报告必须记录当前正文路径 `body_path` 和 `body_text_sha256`（以 UTF-8 解码并统一换行为 `\n` 后的 SHA-256；可直接采用 `python3 scripts/fuben_run.py 作品/NN_主题 --json` 输出的 `inputs.body_text_sha256`）。这是**技术绑定**，防止旧结论给新稿背书。报告哈希与当前正文不一致时，报告状态只能是 `STALE/PROVISIONAL`，不得为新稿背书。缺 `body_path` 或缺 `body_text_sha256` 的报告，都不能拿来证明当前正文已经审过。

最低限度写成：

```md
body_path: `作品/NN_主题/正文.md`
body_text_sha256: `<64位哈希>`
review_status: PROVISIONAL / BLOCK / FIX / APPROVE
十二问结论：逐问一行（引行号）；红线：无烟三文件「烟」0 命中（搜索词：烟/吸烟/点了根）；账目手算 N 条全对；虚构声明：有/无
```

## 4. 事实与技术核对作底线（不是创作结论）

核对本篇真正涉及的事实、指代、因果、账号约定和来源；分清角色误信、倒叙、虚构和现实断言。精确数字确实错误要修，但不能把修几个字当作完成创作审核。

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --json            # 输入/算术/指标（BLOCK=确定的输入或算术错误）
python3 scripts/fuben_run.py 作品/NN_主题/正文.md --style     # 可选：AI 腔句式候选，advisory
python3 scripts/fuben_products.py 作品/NN_主题                # 阶段产物与哈希绑定是否齐全
```

- 脚本只出两类东西：**确定的输入/算术错误**（必须清零）与**描述性数字**（字数/行数/估时/AI 腔候选）。
- 结构、节奏、禁词、对白、体量**不再有机检门禁**——判断依据是本文件十二问与 fuben-write 的提示词规则。
- **PASS 只说明没有已检出的机械错误，不评开头、爽感或可发布。**

**创作结论与机器状态分开：**
- `FIX`：开头留不住、主线散、蓄势无兑现、伏笔生硬或侧面无效，即使机检全绿也不能放行。给位置和实改。
- `APPROVE`：当前范围内，创作目标有具体正文证据且无已知阻断。不是"没查出错"就批准，也不是流量预测；solo 不升级成独立认定。
- `BLOCK`：明确不能按要求交付的问题尚未解决。
- `PROVISIONAL`：完成当前可做的判断，但关键素材或证据不足；说明缺什么，不假装全文或成片已经通过。

## 5. 仅在制作／发布任务中审媒体

用户要求后才读取 [成片逐镜清单](references/成片逐镜清单.md)，审真实声音、字幕、镜头及素材权限。字数/语速、ffprobe 元数据都不是听完视频。`fuben_release.py` 只做证据验收；改稿使旧版本证据失效，工具通过不等于账号主授权或平台通过，不代发。
