# 人生副本审核

**审的是观众有没有继续听的欲望、期待是否得到兑现，不是检查表是否全绿。** 本账号默认重视强开头、爽感、伏笔钩子和侧面描写；以本次用户要求为准，不拿“日常可以平淡”驳回明确的创作目标。能独立审则独立审，否则标 solo 自检；不冒充多 Agent 会审。

**判据来源**：[fuben-craft 手艺层](../story-short-write/references/fuben-craft/README.md)。审稿时读
[口播腔调与反AI味.md](../story-short-write/references/fuben-craft/口播腔调与反AI味.md) 的 §B/§C/§D，
再按问题类型读对应的那一个文件（追看→开场与钩子；笑点→笑点机制；共情→侧面与共情；爽感→爽点兑现；结构→结构与曲线）。
**禁止按 `_archived/人生副本实录_v1_归档.md` 的旧配额验收**（场景数、每场行数、时间标签数、内联说话行数、
setup-payoff 对数、字数区间全部作废）。实证：`作品/80_练薄肌的人活在成都/_运行/03b_审读.md` 按那套条款判「达线」，
用户仍然裁定「看不懂、是流水账」——**配额全绿和好看是两件事。**

## 1. 先读当前正文，判断追看是否成立

确认范围是全文、短版、切条还是成片，读对应的实际版本。已有设定和来源按需查；旧报告、作者自评、场面表不能代替正文。没有正文就不做全文判断；没有音视频仍可审文本，但不声称听感或画面已验证。

优先检查以下问题，直接引用原句说明，不要求作者补表：

- **开头为什么值得继续听？** 观众产生了什么具体疑问、期待或情绪？若只复述题目、介绍身份、描述普通动作，没有牵引，就指出应从哪场冲突、哪个反常后果或哪个动作切入。不能用抽象的“开头不错”放行。
- **中间在推进，还是在换段闲聊？** 关键行动是否改变处境；前一个小兑现是否带出下一层期待？指出最早可能划走的具体段落及原因。刺激开头接流水账仍是失败。
- **爽点有没有真正演出来？** 蓄势在哪里，兑现是哪句/哪场，兑现后谁的处境、选择或话语权变了？若关键时刻只剩“众人震惊”“你终于赢了”，要求展开交锋和反应，不靠旁白宣布爽。
- **伏笔和侧面描写是否有效？** 前面的细节能否支持后面的揭示；有没有临时空降的答案？对手、旁人或环境的变化是否帮助观众判断并推动后续，而不是装饰性的表情堆砌？
- **要搞笑的题，笑点是结构还是梗？** 逐个笑点问：它用的是[九种引擎](../story-short-write/references/fuben-craft/笑点机制.md)里的哪一种？答不出来的就不是笑点，是热梗引用或形容词。热梗原句被旁白搬运（「大家管这个叫 X」）、一场自欺被压成一句总结（「他论证了一晚上」）、败者收场只有「全场安静」而没有静物定格，都要指出来并给展开后的写法。
- **观众认得出自己吗？** 抽象焦虑（羞耻、匮乏、疲惫、被辜负）有没有过身体／器物／数字[三通道](../story-short-write/references/fuben-craft/侧面与共情.md)之一？痛点场景是不是国民级的（排队、办卡、点外卖、家长群）？没有对照组的反杀缺燃料——受难者的戏在主角开火之前吗？
- **结尾是口号还是器物／动作？** 对仗句、零和句、人生格言收束＝说教税（`拆文库/_速拆卡.md` 短板预警：结尾 3 分区＝直白兑现无余味）。指出来，并给一个用器物或动作收束的版本。

不强制每篇同一种反杀，也不发明固定节点数、情绪分、百分比或动作密度。判断的是具体效果，不是术语命中。若本次用户已指出开头弱或没爽感，先解决这些问题，不转去处理与之无关的工程待办。

### 五维评分（定位用，不是通过证明）

按 [口播腔调与反AI味.md §D](../story-short-write/references/fuben-craft/口播腔调与反AI味.md) 打五维，每维 1–10：

| 维度 | 审什么 |
|---|---|
| 追看 | 前 8 行有没有具体疑问；最早可能划走的是哪一段 |
| 笑点 | 每个笑点用的是哪种引擎；剂量与安全线 |
| 共情 | 抽象词有没有过三通道；痛点选址是否国民级 |
| 兑现 | 四拍齐不齐；绝杀台词观众 30 秒后能否复述 |
| 腔调 | 行节奏；命中几条 slop；有没有误伤 §C 保留清单里的人味 |

三条纪律：**①每一分必须挂原句**（「笑点 6 分」无效，「笑点 6 分：第三幕『他论证了一晚上』把戏压成总结，引擎 8 需要三轮降档」有效）；
**②总分 <35 建议回炉，但创作结论（FIX/APPROVE/BLOCK/PROVISIONAL）按证据下，不按总分下**；
**③不许为了刷分建议往里塞器物、数字和旁观者**——`scripts/fuben_policy.json` 的 `creative_rules` 全部为 `null`，
`metric_thresholds` 是 `descriptive_only`，本表不推翻这个决定。

## 2. 给诊断，也给能用的改写

主控按 [副本 Agent 方法·审读与返工](../story-short-write/references/genre-styles/人生副本_Agent方法.md#3-审读先指出失去追看欲的位置再决定退到哪一步) 路由：切口/主线不成立回策划，关键戏没展开回主笔，只有表达问题才局部润色。独立审读只收当前正文、brief和必要事实，不以作者自评或旧通过报告作依据；独立审读者给诊断，主控再委派改稿，不让“我改了”代替复审。用户只要审核时不自动改稿；只研究Agent时不启动创作。

保留有效的声音和段落。开头弱，给改后的开头并接到第一段实质发展；爽点落空，展开那一场；主线散，重排事件，不只改几个形容词。不能只换一句钩子，后面照抄旧流水账。

用户要口头意见就直接回复；要改稿就交改稿。说明改动为何服务于追看与兑现，但不要让解释比正文更长。只在用户需要时落审核报告，记录当前版本、solo/独立方式、关键原句、改法和仍未验证的项。没有真实偏好或平台反馈，不许报“必爆”“恢复原作水平”或虚构胜率。

## 3. 读通专项：从当前正文取证

在创作效果之后，单独通读**当前完整稿**。不要只读被点名的句子，也不要拿写前设定、台账或旧报告代替正文。至少检查：

1. 标题承诺与主要事件是否吻合；判断事件承担的功能，不用热词、词频或名词次数判跑题。
2. 物件、食物和人物是否有未解释的身份、位置或状态漂移；先判断是否同一实例、是否发生了合理转移。
3. 时间表达是否指向同一事件，起止点能否接上；不同事件的“两周／一个月”和夜间状态不自动矛盾。
4. 多人场景中的代词是否有清楚先行对象；目标是可辨认，不强迫所有配角取名。
5. 问答是否有观众可理解的回应关系；玩笑、借代和故意答非所问可以保留，但须有语境支撑。
6. “第一／第二／第三”等序列是否维持同一分类，或在改变压力来源时给出明确转向。
7. “连、却、因此、再然后”等连接词所承诺的递进、转折或因果是否成立。
8. 明确计数主张是否准确，并分别确定外层句子与内层短语的计数边界。
9. 专业术语、俗语、角色自我安慰、作者旁白事实和玩笑是否混淆；未核实说法不能当专业事实。
10. 关键转折是否由人物需要、情绪、关系或认识支撑，结尾是否以行动兑现而非只输出金句。
11. 修改后是否遗留旧场景、旧食物名、旧时间、旧称呼、旧字数主张或旧审核结论。

跨句问题必须同时给两端证据。对每个发现写：

```md
- 规则或问题类型：
- 文件与原文位置：
- 原句及相关对照句：
- 为什么影响理解：
- 确定错误 / 待确认 / 可接受表达：
- 最小修复建议：
- 复核结果：
```

“确定错误”只用于当前文本已有充分证据的问题；需要确认对象、时间起点、玩笑意图或历史版本时标“待确认”。不为凑数量升级严重度。

## 4. 返工允许局部改，但必须查关联依赖

场景、关键食物／道具／人物称呼、时间点或跨度、标题核心概念、主要压力源、结尾金句或字数主张发生变化时：标明改动对象，查找全文直接引用和间接指代，修复受影响段落，再检查场景接缝、题意回扣与当前完整稿。改稿后必须重新审读并生成对应新版本的结论，不能复用旧稿的“通过”。全文重写不是默认答案，也不能免除复核。

审核报告必须记录当前正文路径 `body_path` 和 `body_text_sha256`（以 UTF-8 解码并统一换行为 `\n` 后的 SHA-256；可直接采用 `fuben_run --json` 的 `body_path` 与 `inputs.body_text_sha256`）。报告哈希与当前正文不一致时，报告状态只能是 `STALE/PROVISIONAL`，不得为新稿背书。最低限度写成：

```md
body_path: `作品/NN_主题/正文.md`
body_text_sha256: `<64位哈希>`
review_status: PROVISIONAL / BLOCK / FIX / APPROVE
```

缺 `body_path` 或缺 `body_text_sha256` 的报告，都不能拿来证明当前正文已经审过。

## 5. 事实和机械检查作底线

核对本篇真正涉及的事实、指代、因果、账号约定和来源；分清角色误信、倒叙、虚构和现实断言。精确数字确实错误要修，但不能把修几个字当作完成创作审核。自动检查只阻断边界明确的错误；物件位置、时间跨度、代词和新名词只能作为语义候选，必须由上述读通专项确认。

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --json
python3 scripts/fuben_run.py 作品/NN_主题/正文_3分钟版.md --profile short --json
python3 scripts/fuben_craft_scan.py 作品/NN_主题/正文.md   # 只读读感扫描，输出带行号候选
```

BLOCK 定位明确错误；REVIEW 人审上下文；NOTE 描述或未评估；ERROR 表示工具未成功。工具缺失就如实说明。机检 PASS 只说明没有已检出的机械阻断，不评开头、爽感或可发布。

`fuben_craft_scan.py` 是**只读的读感扫描**，不是门禁：它按 [口播腔调与反AI味.md §B](../story-short-write/references/fuben-craft/口播腔调与反AI味.md) 的十二条给出带行号的候选（口号收尾、梗原文搬运、假动作主语、抽象总结代替戏、碎行堆叠、未解释术语、时间戳分段器、排比三件套、情绪播报、万能旁观者、旁白讲解员、工程词泄漏），并列出 §C 保留清单命中的疑似人味（方言、俚语、角色胡诌），提醒**不要误清**。它不打分、不判好看、永不 BLOCK，也不写进创作结论；用它省通读时间可以，用它代替通读不行。

**创作结论与机器状态分开：**
- `FIX`：开头留不住、主线散、蓄势无兑现、伏笔生硬或侧面无效，即使机检全绿也不能放行。给位置和实改。
- `APPROVE`：当前范围内，创作目标有具体正文证据且无已知阻断。不是“没查出错”就批准，也不是流量预测；solo 不升级成独立认定。
- `BLOCK`：明确不能按要求交付的问题尚未解决。
- `PROVISIONAL`：完成当前可做的判断，但关键素材或证据不足；说明缺什么，不假装全文或成片已经通过。

## 6. 仅在制作／发布任务中审媒体

用户要求后才读取 [成片逐镜清单](references/成片逐镜清单.md)，审真实声音、字幕、镜头及素材权限。字数/语速、ffprobe 元数据都不是听完视频。`fuben_release.py`只做证据验收；改稿使旧版本证据失效，工具通过不等于账号主授权或平台通过，不代发。
