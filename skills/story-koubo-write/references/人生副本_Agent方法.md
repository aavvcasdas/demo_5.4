# 人生副本 · 从 GitHub Agent 迁移的创作方法

这是主流程及子 Agent 的执行分工，不是给作者新增表格。创作目标沿用 [主profile](人生副本实录.md)。来源与适配位置见 [借鉴说明](../../../docs/短视频Agent借鉴.md)。只加载本次负责的阶段；研究/改造 Agent 的任务到方法落地为止，不自动写样稿。

**每个角色只拿本轮需要的手艺切片**（[fuben-craft/](fuben-craft/README.md) 加载表）。把整包塞给每个角色，等于让每个人重读全部规则——`人生副本实录.md` v13 已经禁止这件事，v15 给出了具体切法，见下面各节的「带什么给子 Agent」。

## 0. 必须有真实调用

本次用户明确要求所有文章生成都调用 Skill / Agent。可用调用入口：①已认证外部执行器；②Arena 会话内按 [arena.runtime.json](../../../arena.runtime.json) 定义的执行通道——主会话逐阶段加载角色文件（story-architect / narrative-writer 的副本职责分支）与本方法执行，产物落 `作品/NN_主题/_运行/`，缺阶段产物视为未调用。两个入口都不可用就停止，不以主会话越过角色直写兜底。以下策划候选、正文及实质改写均经上述通道完成，主控负责路由；不能把读取本文件当成已调用。

## 1. 主控委派选出能成立的开场，不直接押第一个想法

**策划的第一个动作是选样本 + 精读原文全文，不是搜索。** 按 [fuben-craft/样本索引.md](fuben-craft/样本索引.md) 的方向表（爽向／搞笑向／扎心向／温情向／悬念向）挑 2–3 篇同型语料，然后：①**其中至少 1 篇的 `拆文库/NN_标题/原文/原文.txt` 全文逐字进上下文**（不是拆文报告、不是 `_meta.json`、不是节点表），并在阶段一产物里留一行复述——*它怎么把一个瞬间写大到能住进去*（感官落在哪、动作链怎么走、时间在哪膨胀）；**复述写成机制提纲（「它有爽点、在 20%」）＝视同没走流程，考点提纲不能生产质地，课文才能**；②读 2–3 篇的 `情节节点.md`（节点的类型／情绪值／手法／字数位置——等于带时间码的分镜）；③读 1 篇的 `写作手法.md`，挑 3–5 项当本篇手法清单。

**不定字数目标**（[口播稿规格.md §B](fuben-craft/口播稿规格.md)）：带位表（切条 ≤400 / 标准 1,150–1,900 / 全长 2,700–3,800，按 **6.4 字/秒**折算）**只在 04c 事后对账**，不在写前当目标。
> 教训：v15 曾要求「定篇幅档并算一遍这个字数装得下几个场面」，`作品/80` 据此算出「还差 330 字」再往里补五处，
> 凑完还是流水账。**凑字数是流水账的第二成因，第一成因是段间只有时间连接词、没有因果连接词。**

**然后才是检索，且必须是真实搜索调用（用户裁决：阶段一不调用搜索即任务失败；arena 一次可并行多路搜索，下限 8 路、单次一批全部并发并留批号）。** 检索前先**深度理解主题**：题眼是什么、谁在受这个处境的罪（受众替谁共情）、情感核、这个主题天然能长出的几类冲突、什么写法算跑题。检索覆盖：本题现实质感、同类真实案例、相邻题材/真实事件、同类传播内容与钩子形态。逐条记录检索词、批序号、来源与取用的质感；借质感不借剧情，不编造来源。

**热梗题的额外一步**：用户点名要用某个热梗时，先考据母版原句、源头候选与实际用法（80 号的教训：「耍起」被当成成都方言，用户当场纠偏「是玩起来，抖音热梗」，见 `作品/80/_运行/06_勘误_耍起词义.md`）。考据结论写进阶段一产物，并规定梗只能从**人物嘴里**出来，不许由旁白介绍「大家管这个叫 X」（见 [笑点机制.md](fuben-craft/笑点机制.md) §梗的正确用法）。

**检索之后产出 3-4 个分类型的剧情方向，交用户选择：爽向、搞笑向、扎心向、温情向、悬念向等，类型集按主题定，"各种类型的都要"是用户明示要求。** 每个方向给：类型标签、一句话剧情线、开场钩子速写（用 [开场与钩子.md](fuben-craft/开场与钩子.md) 的六种模板之一并写明是哪一种）、主峰兑现路径（写清 [爽点兑现.md](fuben-craft/爽点兑现.md) 四拍里「加码」那一拍是什么，缺这一拍的兑现是廉价的）、借用的语料机制（`拆文库/NN` 编号 + 手法名，来自该篇 `写作手法.md`）、借用的检索质感、主要风险（含文体税：选了糖水／软文／警世体就要说明怎么补对抗）。搞笑向的方向必须写明打算用哪几种笑点引擎。已存在成稿的作品，第一选项固定为【保留现版·校准】。**未获用户选定，不得开写正文**（用户授权"你定"时由主控代选并记录理由）。

借鉴 writing-loop 的设计候选竞争，内部只淘汰硬伤方向（接不上兑现/跑题/只有噱头），不再有内部单独定稿这一步。已存在成稿的作品，第一选项固定为【保留现版·校准】。**未获用户选定，不得开写正文**（用户授权"你定"时由主控代选并记录理由）。

在简报或阶段一产物中写一段轻量的 `本篇题意约定`，只服务本篇，不要求另建表格：标题核心概念、用普通话解释实际在写什么、主角想得到什么、主要阻力、关键事件如何体现阻力、关键选择为什么改变、结尾用哪个行动兑现题意。判断靠事件功能而不是热词占比；题意发生明显变化时，重新核对关键事件与结尾，不只替换标题和口号。

借鉴 writing-loop 的设计候选竞争，但只做轻量切口比较，不生成多个完整稿，也不启动其工单系统。

- 新题尚无明确开头时，内部比较两个**驱动力不同**的短开场，例如观众先知真相等人露馅，或观众只见反常结果等解释。不是同一意思换两个形容词。用户已定开头时不凑候选。
- 每个切口接一个“往下能发生的关键变化”：观众究竟在等什么，靠哪场行动兑现。只有噱头、接不上正文的切口淘汰；不是挑措辞最吓人的。
- 从参考原文提炼“怎样蓄期待、怎样兑现”的机制，不只提炼句长和词汇。先想清关键兑现，再把观众事后能看懂的线索放进前文；只有设定里知道、不在正文出现的信息不能算伏笔。

确定后，把本题事实、选中的切口、主角要争取的事、核心兑现及必要线索交给主笔；有对标时再传一段与本题相近、能看到蓄势到兑现的原文及其借用机制，不只传“参考这个风格”，也不塞整库分析。用一小段内部交接即可，不要求作者填卡或审批。仍没有值得追的事件，就重选切口，别先写长篇再用审稿救。

## 2. 主笔把爽点写成连续发生的戏

由实际调用的 `narrative-writer` 完成；主会话不得代写。借鉴 drama-skills 的场景策略与反应后果：

- 在关键场面里写人物怎样争取、遭到什么有效阻力、为什么换招、哪一步改变局面。别用反复质问/否认拖长，也别把最关键的反击压成一句“后来你解决了”。这不是要求每段都有反派。
- 开场制造的压力尽快产生行动。背景在行动需要时补；小兑现可以释放一部分情绪，同时让新的选择或后果牵引下文。完整口播要在本篇偿还核心期待，不复制付费短剧的跨集吊胃口。
- 明牌时，让观众期待对手何时认清局面；暗牌时，让异常细节累积到揭示。不要为了惊讶隐去理解眼下行动所必需的信息。
- **侧面是主角行动留下的影响。** 对手改条件、旁人改变站位/称呼/选择、某件东西换了持有人，都能表现话语权变化。单写脸白、震惊、沉默不自动构成爽点：他原本能做什么，现在为什么不能再做？
- **不要让配角替主角爽。** 配角可以施压、作见证、付出代价或助攻，但若最难的一步全靠旁人说漂亮话、送证据、无条件帮忙，主角的反击就被拿走了。保留主角自己的策略与选择。

**笑点必须演出来，不能被总结掉。** 用户要搞笑时，主笔按 [笑点机制.md](fuben-craft/笑点机制.md) 的九种引擎写：
一场自欺至少要三轮降档（讲道理 → 上证据 → 耍赖），不能压成「他论证了一晚上」；
对手要有台词规格（好奇句或冷淡句），不能只当背景；
败者收场要给静物定格（一个具体姿势 + 一件举着的道具），不是「全场安静」。
梗从人物嘴里出来，一条稿里同一个梗 ≤3 次。

**带什么给主笔**（只给本轮这几样，不整包转发）：

| 本次方向 | 交给主笔的手艺切片 |
|---|---|
| 全部方向 | [开场与钩子.md](fuben-craft/开场与钩子.md) 的模板段 + [口播稿规格.md](fuben-craft/口播稿规格.md) §B 字数带 / §C 排版五条 / §E 一遍听懂 Gate + [口播排版与反流水账.md](fuben-craft/口播排版与反流水账.md) §A 三判据 / §B 三件事 / §D 保留清单 |
| 爽向 | + [爽点兑现.md](fuben-craft/爽点兑现.md) 全文 |
| 搞笑向 | + [笑点机制.md](fuben-craft/笑点机制.md) 全文 + [爽点兑现.md](fuben-craft/爽点兑现.md) §对手设计 |
| 扎心向 | + [侧面与共情.md](fuben-craft/侧面与共情.md) 全文 |
| 温情向 | + [侧面与共情.md](fuben-craft/侧面与共情.md) §延迟披露 / §型二让位 + [爽点兑现.md](fuben-craft/爽点兑现.md) §不反杀的题怎么写爽 |

| 同型样本 | + 精读那 1 篇的 `原文/原文.txt` **全文**（这一篇不给摘要、不给节点表）+ 另 1–2 篇的 `情节节点.md` |

只交所需正文。候选淘汰理由、素材研究和编排术语不混进口播。**设计语言（「伏笔」「钩子」「侧面」「第一幕」「字数约」）出现在正文里属于工程词泄漏，直接删——口播稿里不许出现创作术语。**

## 3. 审读先指出失去追看欲的位置，再决定退到哪一步

可调用新上下文的 `story-architect` 做创作审读；只给当前正文、brief和必要事实，不给作者自评、旧通过报告或“这里很爽”的解释。没有独立调用能力就由主会话自检并标 solo，不伪装多人意见。

让审读者回答：开场使我等什么？哪一段开始不再推进？哪个兑现没有被演出来？侧面反应究竟改变了什么？要搞笑的题，每个笑点用的是九种引擎里的哪一种（答不出来的就不是笑点，是梗或形容词）？哪个抽象词没有过身体／器物／数字三通道？结尾是口号还是器物／动作？引用实际文字与前后行动，不能靠规则命中或总分判好看。

审读按 [`fuben-review`](../../fuben-review/SKILL.md) 的五维打分（追看／笑点／共情／兑现／**口播**，各 1–10），**每一分必须挂原句**；总分只用于定位问题，不作为通过证明，也不写进创作结论。「口播」维核的是：篇幅够不够装下三个场面、均行长与空行合不合排版、听感三问标记了几处（判据见 [口播稿规格.md §B/§C/§E](fuben-craft/口播稿规格.md)）。**禁止按 `_archived/人生副本实录_v1_归档.md` 的旧配额验收**（场景数、每场行数、时间标签数、内联说话行数、setup-payoff 对数、字数区间全部作废）——`作品/80/_运行/03b_审读.md` 就是这么审的，它验的是一套现行 profile 里不存在的条款，稿子达标了却仍然被判「看不懂、流水账」。审读前确认自己引用的是 v15 与 fuben-craft，不是归档包。

借鉴 short_drama_agent 的分层返工，但不用它的机械密度评分：

| 创作问题 | 主控交回哪里 | 改什么 | 对照哪个文件 |
|---|---|---|---|
| 切口平、欲望/阻力不成立、钩子无处兑现 | 主控／`story-architect` 重构 | 换入场与事件组织，重新连起承诺和兑现；不只换第一句 | [结构与曲线.md](fuben-craft/结构与曲线.md) §三步定骨架 · [开场与钩子.md](fuben-craft/开场与钩子.md) §六种模板 |
| 没有对手、没有蓄势，爽点靠旁白宣布 | 主控／`story-architect` 重构 | 补「加码」那一拍；给对手话术工具箱与利益 | [爽点兑现.md](fuben-craft/爽点兑现.md) §四拍结构 · §对手设计 |
| 搞笑向不好笑：只有梗引用，没有结构 | `narrative-writer` 重写关键场 | 指出该场用哪种引擎，展开成 2–3 轮降档；补对照组与静物余波 | [笑点机制.md](fuben-craft/笑点机制.md) §九种引擎 · §反例解剖 |
| 观众认不出自己：抽象焦虑直接播报 | `narrative-writer` 重写关键场 | 过身体／器物／数字三通道；痛点换到国民级场景 | [侧面与共情.md](fuben-craft/侧面与共情.md) §共情翻译器 · §痛点选址 |
| 主线成立，但反击跳过、伏笔没落正文、侧面成捧哏 | `narrative-writer` 重写关键场 | 补人物主动选择、有效阻力、线索和兑现后的局面变化 | [侧面与共情.md](fuben-craft/侧面与共情.md) §侧面四型 |
| 篇幅不够、排版是电报体、关键瞬间没膨胀 | `narrative-writer` 扩写场面 | **先把段间的时间连接词换成因果连接词**，再把没展开的关键一拍写慢；不加形容词、**不为进带位加字**；排版回到手写稿的 8.5–10.7 字/行、零空行、判词与数字独占一行；关键一拍的判据是「观众能不能住进去」，不是行数 | [口播稿规格.md](fuben-craft/口播稿规格.md) §B / §C + [口播排版与反流水账.md](fuben-craft/口播排版与反流水账.md) §B1 |
| 戏已经成立，只是啰嗦、声线或局部衔接不顺 | `narrative-writer` 局部修 | 保留有效剧情和力度，不退回重写全篇 | [口播排版与反流水账.md](fuben-craft/口播排版与反流水账.md) §E 改稿顺序 |

**顺序不可换**：先篇幅与结构，再场面与侧面，最后才是词句。最常见的错误是把最后一档当第一档做——
稿子篇幅只有语料的 40%、没有对手、没有蓄势、没有兑现，却花三轮调句式、数时间标签。
**口播稿不做「去 AI 味」清零**（`story-deslop` 已把 profile=fuben 分流出去），别把返工预算花在清句式上。

审读返回“具体原句＋损失＋返工层级＋修订目标”；不擅自代写整篇。完成创作审读后，再按 `fuben-review` 做一次独立的**读通专项**：从当前正文逐场检查题意与事件功能、实体/人物身份与状态、时间锚点、代词先行对象、问答关系、序列承诺、连接词逻辑、计数边界、术语/玩笑身份和转折支撑。跨句问题必须给两端证据；合理转移、不同实例、不同事件和有语境的玩笑不得机械判错。

改完再由审读看问题是否解决且主线仍成立，不凭写手回复“已修改”通过。局部修改涉及场景、食物/道具、人物称呼、时间、题意、压力源或结尾计数时，先检索全文直接引用与间接指代，再复核当前完整稿。审读结果绑定当前正文的 `body_path` 与 `body_text_sha256`；任一变化后旧结论失效。审读没执行或没有实质回复就标未完成，不默认放行。沿用 `fuben-review` 的创作结论，不另造文学分数或字数门禁。

### 3.5 审读的后半：联网搜索对标（必做，不是可选项）

用户对「审核」的定义是**生成完再次查看并搜索网页**。前半（复读 + 听感三问 + 口播规格核对）做完，
审读必须真跑一次搜索，并把结果写进 `04c_联网对标.md` 与审核报告的「联网对标」节。**未写 = 审核未完成。**

| 查什么 | 搜什么 | 用来判什么 |
|---|---|---|
| **同题带位** | 同题近 30 天的爆款口播（同人物设定／同城市／同焦虑） | 开场第一句是不是已经被用烂；时长档选错没有；本篇钩子比同题慢几秒 |
| **热梗时效与出处** | 稿内每个热梗的**当前**含义、出处、是否过期、是否有争议 | 过期或有争议的梗**直接换掉**（不是加注释）；出处与稿内用法不符＝观众出戏 |
| **外部事实** | 稿内涉及的价格、政策、地名、品牌、行业流程、时间线 | 事实错误要修；虚构与角色误信要分清，别把虚构判成错误 |

**纪律**：搜到的是**带位与时效**，不是写作许可——同题爆款怎么写不构成本篇必须照抄的理由，借的是处理方式，
不是人物经历与原句。搜索结果与 `拆文库/` 语料冲突时**语料优先**（语料是本账号已验证的 10w+ 原文，
搜索结果是全网平均值）。热梗题的考据结论要与阶段一产物里的考据对齐，冲突时以最新一次搜索为准并记录改动理由。

**不许做的事**：不写脚本自动删改正文；不把搜索命中当成机械闸；不因搜到某个「爆款公式」就往稿里塞
（拒录清单见 [口播稿规格.md §G](fuben-craft/口播稿规格.md)）。

## 4. 只派需要的角色

`character-designer` 只在人物动机、台词博弈或侧面反应需要补强时参加：检查各人维护的利益，反应为什么改变下一动作，是否全成了给主角鼓掌的工具人。不必每篇都调用。

主控负责委派和返工，子 Agent 不递归拉团队。默认一轮成稿、一轮创作审读，必要时定点返工；方向仍有争议就说明争议，不循环刷“通过”。这些是创作分工，不声称已产生真实观众反馈。

原项目的自动提交、跨集票据、固定台词/伏笔配额、缺模型返回固定剧情等做法不引入。本仓普通小说流程、事实底线和发布授权保持各自边界。
