# story-koubo-write：人生副本口播稿写作

**本 Skill 只写口播稿。** 普通短篇小说走 [`story-short-write`](../story-short-write/SKILL.md)，
长篇走 `story-long-write`。两者的规格完全不同——口播稿没有章，只有秒；不靠读，靠听一遍就懂。

## 文章生成必须真实调用 Skill / Agent（用户明确要求）

所有正文生成、续写、重写、试写及候选片段，必须由对应 Skill 的真实执行流程调用创作 Agent 完成。
主会话只能整理用户要求、调度、核对和保存实际 Agent 返回的内容；不能自己生成文章后补写调用说明。

执行入口：已认证外部执行器，或 Arena 会话内按 [arena.runtime.json](../../arena.runtime.json)
（路由见根 [AGENTS.md](../../AGENTS.md)，说明见 [docs/Arena运行时.md](../../docs/Arena运行时.md)）
的 `fuben-write` 管线逐阶段执行并落 `作品/NN_主题/_运行/` 阶段产物。

> **配置缺失时**：`arena.runtime.json` 或 `AGENTS.md` 读不到，就**报告 `BLOCKED: runtime config missing`
> 并给出缺失路径**，不要用「我直接写一版」兜底。这两个文件曾在沙箱回滚中丢失过
> （见 `作品/80_练薄肌的人活在成都/审核报告.md` 的「环境事故披露」），静默兜底会让稿子脱离角色与阶段产物。

## 二、口播稿规格（与小说设定的差别，一眼看清）

完整对照表见 **[references/fuben-craft/口播稿规格.md](references/fuben-craft/口播稿规格.md) §A**。摘要：

| 小说设定（不适用） | 口播稿设定 |
|---|---|
| 章、场景数、每场行数 | **时长档 → 字数带**：切条 ≤60s／≤400 字 · 标准 3–5 分／1,150–1,900 字 · **全长 7–10 分／2,700–3,800 字**（按 **6.4 字/秒**对账，不是行业默认的 3–4） |
| 付费点、跨集吊胃口 | **段内钩子 + 回位钩**（>180s 每 30–45 秒一个「你」行）；期待必须在本篇偿还 |
| 情绪拉扯 Phase 1–4 | **秒级节奏图**：0–3s 具体的人做具体的事 / 15s 第一个可看见的场面 / 30-60-90s 各一个爆点 / 末 20s 判词+器物 |
| 去 AI 味清零、句式配额 | **一遍听懂 Gate**：三条硬规矩 + TTS 听感三问（≤3 处） |
| 读拆解摘要／考点提纲 | **精读原文全文**——「考点提纲不能生产质地；课文才能」 |
| 十二列表格、角色配额 | **场面表五要素**：在场者／地点／进行时动作链／一句转述引语／一件可拍器物；关键瞬间 ≥12 行逐拍 |
| 审稿＝跑脚本找问题 | **审稿＝复读 + 搜索网页** |

**排版五条**：一行一个可朗读的意群（12–20 字）· 判词与数字独占一行＝气口 · 连续 ≤4 字短行不超过 3 行 ·
空行只做段落分隔（一篇 ≤6 处）· **零标点**是账号约定，意群之间用空格。

> **实测依据**：语料原文（18 篇真抖音 ASR）均行长 8.5–10.7 字、0 空行；作者自存的回归夹具
> 17.2–17.8 字、0 空行；而 `作品/79`、`作品/80` 交付稿只有 7.2–7.4 字、**62–63 个空行段**，
> 篇幅是全长档下限的 58% 与 **40%**。**装不下三个场面，就没有剧情**——这是流水账的第一成因。

## 三、流程

按 [arena.runtime.json](../../arena.runtime.json) 的 `fuben-write` 管线逐阶段执行，产物落 `作品/NN_主题/_运行/`。
角色分工与**每个角色只拿哪几片手艺**见 [references/人生副本_Agent方法.md](references/人生副本_Agent方法.md)。

| 阶段 | 做什么 | 产物 |
|---|---|---|
| **00 简报** | 题意、账号约定、执行通道与版本 | `00_简报.md` |
| **01 精读 Gate + 样本选择 + 主题深读 + 检索 + 分类型方向** | **第一个动作是精读，不是搜索**：按 [样本索引](references/fuben-craft/样本索引.md) 选 2–3 篇同型语料，把其中至少 1 篇的 `拆文库/NN_*/原文/原文.txt` **全文**读进上下文，复述「它怎么把一个瞬间写大到能住进去」；**不要预估字数**（字数是写完的结果，凑字数是流水账第二成因）；然后才做主题深读与并行检索（下限 8 路，单批全并发，留批号）；产出 3–4 个分类型方向交用户选 | `01_主题深读_检索与剧情方向.md` → **用户选定方向** |
| **02 成稿** | 主笔写连续关键戏，不是复述节点 | `02_初稿.md` |
| **03 创作审读** | 找追看断点，指到原句与影响 | `03_审读.md` |
| **04 返工定稿** | 按结构／场面／表达分层返工，**顺序不可换** | `04_返工.md` + `正文.md` |
| **04b 复读** | 完整复读 + 听感三问（≤3 处）+ 口播规格核对（篇幅档／均行长／空行数／气口行） | `04b_复核.md` + `审核报告.md`（含 `body_path` 与 `body_text_sha256`） |
| **04c 联网对标** | **真跑搜索**：同题近 30 天爆款带位、热梗时效与出处、外部事实 | `04c_联网对标.md` |
| **05 机检** | `python3 scripts/fuben_run.py 作品/NN_主题/ --profile full --json` | `05_机检.json` |

**未获用户选定方向，不得开写正文**（用户授权「你定」时由主控代选并记录理由）。
**不调用搜索即任务失败**（用户裁决）。缺阶段产物＝调用未发生，不得声称走了管线。

## 四、审核 = 生成完再次查看 + 搜索网页

判据在 [`fuben-review`](../fuben-review/SKILL.md) §1.5。两半都必须做，缺一半就是没审。

- **前半（复读，离线）**：完整读当前正文 → 听感三问逐处标记（哪里要回听／哪里要脑补因果／
  哪里念出来不像人话，一稿 ≤3 处，超出回写再读）→ 核口播稿规格 → 核反流水账三件事
  （[判据](references/fuben-craft/口播排版与反流水账.md)）→ 指出哪句抓住了什么期待、哪段让期待断掉、
  最好的一刻是否真正展开、要搞笑的题每个笑点用的是哪种引擎。
- **后半（联网，在线）**：真跑搜索并写进审核报告「联网对标」节，**未写 = 审核未完成**。
  查三件事：①同题近 30 天爆款的开场写法与时长带位；②稿内每个热梗的**当前**含义、出处、是否过期或有争议
  （过期就换掉，不是加注释）；③稿内涉及的价格、政策、地名、品牌、行业流程、时间线。
  **搜到的是带位与时效，不是写作许可**；与 `拆文库/` 语料冲突时**语料优先**。

**改稿顺序从大到小**：篇幅 → 排版 → 场面膨胀 → 处境改变 → 秒级落位 → 一遍听懂 → 个别词句。
**不要在最后一档上花时间**，也不要花时间在「清 AI 味」上——那不是本赛道的病。

## 五、不许做的事

1. **不写脚本自动删改正文。** 口播稿不做「去 AI 味」清零（`story-deslop` 已把 profile=fuben 分流出去），
   自动改写出来的稿子百分百有问题。曾加过的 `scripts/fuben_craft_scan.py`（正则找文体问题）已删除：
   它找不到开头追看、笑点引擎、蓄势兑现、共情通道，而这四项正是用户点名要的。
2. **不把计数做成闸。** `scripts/fuben_policy.json` 已定 `creative_rules` 全为 `null`、
   `metric_thresholds: descriptive_only`、`ai_style_patterns: REVIEW`，`scope` 写明
   「机械阻断只用于明确的输入/算术/契约错误……不自动判文笔、事实真假或流量」。
   本仓 2026-09-19 实测过：给密度计数补上动作流后三篇全绿，**稿子仍是流水账**。
3. **不加载 `_archived/` 旧配额包。**
4. **不把机检 PASS 当写好了。** `fuben_run.py` 查的是日期、算术、事实锁、账号品牌、输入完整性，
   **不查钩子、笑点、共情、侧面、剧情**。
5. **不搬热梗原句当剧情。** 梗只能从人物嘴里出来、当背景一句带过；旁白介绍「大家管这个叫 X」不是笑点。
6. **不搬外部公式。** 拒录清单见 [口播稿规格.md §G](references/fuben-craft/口播稿规格.md)：
   「每句≤15字」「口播 3–4 字/秒」「完播 30%+」「远程规则注入」「带货线全套」一律不采。
