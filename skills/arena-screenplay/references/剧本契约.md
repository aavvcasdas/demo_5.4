# Arena 单集剧本契约

## 1. 产物只有一个主文本

当前版本是 `剧集/<EP>/剧本.md`。简报、来源记录和审读是旁证，不是正文的第二份副本。任何产物只要没有 `body_path` 和当前正文哈希，就不能说它审过当前稿。

推荐状态：

- `DRAFT`：主笔仍在写；
- `MECHANICAL_PASS`：格式检查通过，但尚未完成编辑审读；
- `PROVISIONAL`：有人读过并记录问题/暂时接受，仍未完成成片或平台验证；
- `READY_FOR_OWNER_CONFIRMATION`：所有必需审读证据齐，但仍须作者/制片人确认；
- `STALE`：正文、素材或契约改变，旧记录失效；
- `BLOCKED`：存在格式、事实或制作硬阻断。

不要使用单独的 `PASS` 表示「作品通过」。

## 2. 最小单集契约

```yaml
episode: EP001
promise: 观众本集要体验什么
protagonist: 谁在行动
goal: 本集行动目标
opposition: 谁/什么阻拦，阻拦策略是什么
turn: 哪个行动改变了局面
payoff: 本集兑现
exit_state: 结尾状态
constraints:
  duration: 可选
  locations: 可选
  cast: 可选
  prohibitions: []
```

没有对手并不代表必须添加一个坏人：制度、时间、身体、误会或主角自己的选择都可以构成阻力，但必须在场景中产生后果。

## 3. 场景最低信息

每个场景至少能回答：

- 谁想在这一场得到什么？
- 谁/什么让他不能直接得到？
- 主角采取了什么具体动作？
- 结果怎样改变下一场的选择？

“发生了很多事”“主角意识到……”不是结果。结果必须落在权限、关系、位置、物件、风险、信息或下一步行动上。

## 4. 改编口播稿的转换表

| 口播稿 | 剧本化处理 |
|---|---|
| 「你住在城中村，家里没有热水」 | 外景/内景中让热水器不出水、房东拒绝维修，主角拿脸盆离开；旁白只保留不可拍的信息 |
| 「教练问你练什么，你说洗澡」 | 让销售/教练现场提问、主角回避或错位回答、对方改变策略；把笑点放在双方行动关系上 |
| 「你把账算清了」 | 让主角打开到店记录、逐项摆出凭证、面对店长的反应；数字成为筹码，不是作者总结 |
| 「你终于赢了」 | 写对方让步、规则改变、关系重新定义或主角付出的代价；禁止旁白盖章 |

## 5. 交付前检查

- 是否还可以删掉人物和场景而不改变结果？能删就合并；
- 是否把 87 稿那种“物件清单＋笑点清单＋算账总结”误当成戏？如果是，回到目标—阻力—行动—结果；
- 是否有一位对手真正做了选择？如果没有，主角的“反打”通常只是旁白；
- 结尾是否由前面的行动造成，而不是新加的判词/互动句；
- 是否有来源、事实和创作虚构的清楚边界。
