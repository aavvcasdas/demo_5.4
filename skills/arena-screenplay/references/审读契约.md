# 审读契约：发现问题，不替正文盖章

## 两层结果

### 机械层
可由脚本确定的事实：路径、UTF-8、场景标题、空场、对白语法、重复正文、审计元话语、正文哈希。机械层可以返回 `PASS`，但字段必须叫 `mechanical_status`。

### 编辑层
必须读正文才能判断：

1. 第一拍是否让观众知道正在发生什么；
2. 主角是否有能驱动行动的目标；
3. 阻力是否有自己的策略；
4. 每场是否发生了信息、权力、关系、情绪、物理状态或风险变化；
5. 对白是否有潜台词，删掉后是否只剩说明；
6. 画面/声音是否承担了 VO 正在代替的戏；
7. 兑现是否由前面的选择造成，结尾是否只是作者总结；
8. 题材、人物、事实和来源是否越界。

编辑层没有完成时，报告只能写 `editorial_status: REQUIRED` 或 `PROVISIONAL`，不能写“通过”“合格”“爆款”。

## 证据格式

每个问题至少包含：

```yaml
severity: BLOCK | FIX | NOTE
scene: EP001-SC002
lines: 24-31
quote: 原文短引
problem: 具体哪里断了
repair: 改成什么动作/冲突/删法
```

“节奏不好”“不够抓人”“AI味”都不是证据；必须落到场景、行动、台词或状态变化。

## 与旧 fuben 检查器的边界

旧 `fuben_run.py`、`fuben_craft.py`、`fuben_claims.py`、`fuben_viral.py` 面向人生副本口播稿。它们可以继续给历史 `作品/` 做回归测试，但不能审 `剧集/` 的剧本；它们的 `PASS` 只代表旧规则未触发，也不能证明 87 稿好看。新项目使用 `arena_screenplay_check.py`，并始终保留人工审读状态。

## 发布前不能偷换概念

- `mechanical_status=PASS` ≠ 剧本审美通过；
- `editorial_status=PROVISIONAL` ≠ 可发布；
- `READY_FOR_OWNER_CONFIRMATION` ≠ 平台已验证；
- 平台数据只能在真实发布后回填，不能由审核报告预言。
